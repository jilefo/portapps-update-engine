# 05 · 验收与排查

## 1. 判定标准

**启动成功 = 包内子进程出现 ＋ Data 目录有新写入**（双维度，缺一不可）。

- 只看进程：进程起来了但界面卡死 / 数据没落地，会漏判；
- 只看窗口：后台型应用本就没有窗口，会误判；
- 只看 Data：有些应用首次启动不写数据，也会误判。

工具链**就在仓库内**：`_shared/tools/`（2026-10-18 已迁入，去掉了绝对路径
硬编码，仓库根由脚本位置自动推导，也可用 `PORTABLEAPPS_ROOT` 覆盖）。
完整说明见 [`_shared/tools/README.md`](../_shared/tools/README.md)。

| 脚本 | 用途 |
|---|---|
| `audit_repo.py` | **结构自检**：纯文本校验，clone 即可跑，CI 用这个（不依赖二进制） |
| `audit_production.py` | 生产级静态审计：开源完备性 / PAL 结构 / 数据落地 / 风险项 |
| `smoke_real.py <Pkg> [秒]` | 单包真启动探针 |
| `smoke_3rounds.py` | 全库 43 单元 × 3 轮 |
| `smoke_clean.py` | 单包干净环境探针（被 `smoke_3rounds` 依赖） |
| `check_custom_nsh.py` | Custom.nsh 病态扫描（引号 / 裸变量 / 管道） |
| `fix_strip_bom.py` | 剥离 Custom.nsh 的 UTF-8 BOM |
| `scan_update_facts.py` | 扫描全部包：入口 exe / App 子目录 / 当前版本 → `_facts.json` |
| `gen_update_strategies.py` | 生成 39 个 `dist/<Pkg>/update.py`（`--clean` 先清旧的） |
| `_shared/update/runner.py` | 批量驱动各包更新脚本，`--check --all --report` |

```bash
python _shared/tools/audit_repo.py                  # 先跑这个，秒出结果
python _shared/tools/smoke_real.py CursorPortable 25
python _shared/update/runner.py --check --all       # 更新检测（39 包，约 6 秒）
```

## 2. 干净环境探针做了什么

```
① 预清 RuntimeData / 残留 junction
② 快照 Data 目录文件清单
③ 剥离污染环境变量后启动
   （ELECTRON_RUN_AS_NODE / NODE_OPTIONS / NODE_EXTRA_CA_CERTS）
④ 轮询：包内子进程、窗口标题、弹框
⑤ 写入对照（Data 新增文件数）
⑥ 有序收场（关应用）+ 清残留
⑦ 判定 PASS / WARN / FAIL
```

第 ③ 步至关重要：宿主若带 `ELECTRON_RUN_AS_NODE=1`，
Electron 应用会以 Node CLI 模式启动并"静默塌陷"，
看起来像是便携包坏了，实则是环境污染。

## 3. 3 轮排查矩阵

为什么要 3 轮：QQ / TIM / QQNT 共享宿主目录（Tencent、Tencent Files），
轮内互相看到对方的 junction 残留，单轮通过不能说明稳定。

```
[R1  1/43] AiPyProPortable ... PASS 16.4s 子进程=2 首窗=None 新增=24 RT残留=1
```

字段含义：`子进程` 包内进程数 / `首窗` 首个窗口出现秒数 / `新增` Data 新写文件数 / `RT残留` RuntimeData 残留数。

**当前基线（2026-10-18）**：43 单元 × 3 轮全部 PASS。

## 4. 排查决策树

```
启动器双击没反应 / 报错
├─ 弹「is missing [Launch]:ProgramExecutable」
│   └─ Launcher/<BaseName>.ini 缺失 → 检查每个 exe 是否都有同名 ini
├─ 弹「便携启动中止」
│   ├─ 真的是他包在运行？ → 正常互斥，先关掉另一个包
│   └─ 不是 → 宿主 junction 残留 → 冷启动清理（含 D 盘真实 Documents）
├─ 静默退出、无进程
│   ├─ ProgramExecutable 路径含中文？ → 检查 ini 编码是否 UTF-16LE
│   ├─ 改的配置在 portableapps/ 还是 dist/？ → 改源树后是否重编？
│   └─ 是否被 ELECTRON_RUN_AS_NODE 污染？
└─ 起来了但数据没写进包
    └─ 查 [Environment] 是否覆盖；必要时加 [DirectoriesMove] 或 Custom.nsh junction
```

## 5. 数据落地专项验证

静态：

```bash
python _shared/tools/audit_production.py
# 看 C 维度：APPDATA / LOCALAPPDATA 是否都指向 %PAL:DataDir%
# 看 A 维度：开源完备性 9 项；看 D 维度：风险项（如 USERPROFILE 重定向）
```

动态（推荐做法）：

1. 启动应用 → 做一点会产生配置的改动（新建文档、改设置）
2. 正常退出（**不要 taskkill**，否则 PAL 来不及还原，会留残留）
3. 检查：`Data\` 下是否新增文件；宿主 `%APPDATA%` 等是否**没有**新增
4. 把整包复制到另一台机器 / 另一目录 → 再启动，确认配置跟包走

## 6. 界面状态判定（WPS 这类 DirectUI 应用）

标题相同不代表界面相同。`GetWindowText` 拿不到的信息，用 UI Automation：

```powershell
Add-Type -AssemblyName UIAutomationClient
$root = [System.Windows.Automation.AutomationElement]::RootElement
# 遍历顶层窗口 → FindAll(Descendants) → 取 Current.Name
[System.IO.File]::WriteAllLines($env:UIA_OUT, $res,
    (New-Object System.Text.UTF8Encoding($false)))   # 必须写文件，别走管道
```

判据示例（WPS）：

| 状态 | UIA 特征 |
|---|---|
| 首页壳 | 含 `新建` / `最近` / `打开` / `暂无打开记录`，UI 文本仅 4~5 个 |
| 空白文档 | 上述控件消失，UI 文本 18~20（功能区） |

## 7. 常用辅助手段

| 手段 | 用途 |
|---|---|
| 截图像素 sha256 比对 | 证明两个界面**逐字节相同**（推翻"开关生效"假设的最强证据） |
| `GetFileAttributesW` & `0x400` | 判定 reparse point（注意失败返回 **-1**） |
| `ExtractIconExW` + `GetDIBits` | 取 exe 图标像素哈希，验证图标是否真的对 |
| `EnumWindows` + `GetClassNameW` | 判窗口归属（`KxWpsPromeMainWindow` 等） |
| 注册表 `Shell Folders\Personal` | 取真实 Documents 路径（本机已重定向到 D 盘） |
