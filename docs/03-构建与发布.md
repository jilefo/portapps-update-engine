# 03 · 构建与发布

## 1. 构建流水线

```
监控分析 → 写配置 → 重编启动器 → 同步 dist → 静态审计 → 动态冒烟 → 发布
   ↑                                                        │
   └────────────────── 不通过则回到这里 ─────────────────────┘
```

### 1.1 重编启动器

```bash
python <仓库根>/_shared\build_launcher.py <PkgName>
python <旧工作区>/scripts\batch_rebuild.py      # 批量
```

编译输出中 `Debug.nsh` 缺失是**预期内**的；真正的失败看 `Error:` 行与退出码。

### 1.2 同步 dist

改源树后必须把 `appinfo.ini` / `Launcher/*.ini` / 图标同步到 `dist/<Pkg>/App/AppInfo/`，
否则运行期读的仍是旧配置。

### 1.3 静态审计（秒级，不启动应用）

```bash
python <旧工作区>/scripts\audit_production.py
```

输出 `reports/生产级审计-<时间戳>.md`，四个维度：

| 维度 | 检查项 |
|---|---|
| A 开源完备性 | LICENSE / README / .gitignore / CHANGELOG / CONTRIBUTING / CODE_OF_CONDUCT / .editorconfig / docs / .github |
| B PAL 结构 | `dist/<Pkg>.exe`、两棵树 appinfo、`Launcher/<Pkg>.ini`、`help.html`、`Other/Source` |
| C 数据落地 | `APPDATA` / `LOCALAPPDATA` 是否指向 `%PAL:DataDir%`；`DirectoriesMove` / `FilesMove` |
| D 风险项 | ini 非 UTF-8、缺 `[Launch]`、缺 `ProgramExecutable`、`ExtractIcon` 目标不存在、重定向 `USERPROFILE` |

### 1.4 动态冒烟

```bash
python <旧工作区>/scripts\smoke_3rounds.py   # 43 单元 × 3 轮
```

判定 = **包内子进程出现** ＋ **Data 目录新写入**，两者同时满足才 PASS。
QQ 系每单元前强制冷启动（杀进程 + 拆宿主 junction）。

## 2. 版本号规范

- `PackageVersion` 用四段式：`主.次.修订.构建`（例 `1.14.10.0`）
- `DisplayVersion` 三段式，面向用户
- 上游软件升级 → 至少 bump 主/次版本，并在 `CHANGELOG.md` 记录

## 3. 发布清单

发布前逐项打勾：

- [ ] `audit_production.py` 四个维度全绿
- [ ] 3 轮冒烟全部 PASS 且三轮一致
- [ ] `dist/<Pkg>/Other/Source/` 含 NSIS 源码副本（合规要求）
- [ ] `THIRD_PARTY_NOTICES.md` 已声明第三方权利
- [ ] `.gitignore` 已排除 `App/` 程序二进制与 `Data/`
- [ ] `appinfo.ini` 的 `[Format] [Details] [Version] [Control]` 四段齐全（**两棵树都要**）
- [ ] `ExtractIcon` 指向的 exe 真实存在（构建期取不到图标会静默降级）

## 4. 开源发布模式

本仓库采用 **「配方开源 + 二进制不分发」**：

| 入库 | 不入库 |
|---|---|
| `appinfo.ini`、`Launcher/*.ini`、`Custom.nsh` | `App/<程序>/` 第三方二进制 |
| 构建/审计/冒烟脚本 | `Data/` 用户数据 |
| 图标、文档、CI 配置 | `*.paf.exe` 等打包产物 |

这样既满足 MIT 开源，又不触碰第三方软件的分发权。
`LICENSE` 尾部与 `THIRD_PARTY_NOTICES.md` 都已明示这一点。

### 首次开源前的收尾

1. `git init` + 首次提交（`.gitignore` 已就位，注意确认没有把 `App/` 提交进去）
2. 确认 39 个包的 LICENSE 均为 MIT 且版权人一致
3. 把脚本仓库 `<旧工作区>/scripts\` 迁到本仓库
   （例如 `_shared/tools/`），否则开源后用户拿不到审计/冒烟工具
4. CI：每个包已有 `.github/workflows/ci.yml`，建议在根仓库补一个
   「静态审计 + 语法解析校验」的最小 CI
