# 02 · 架构与目录规范

## 1. 三树结构（2026-10-19 迁移后）

每个包的资产分布在**三处**，用途完全不同（混淆它们是最高频的返工原因）：

```
<仓库根>/（D:\Projects\PortableApps）
├── <Pkg>Portable/
│   ├── portableapps/                 ① 构建输入（源树，入库）
│   │   ├── App/AppInfo/
│   │   │   ├── appinfo.ini           包元数据（平台与构建器读取）
│   │   │   ├── Launcher/
│   │   │   │   ├── <Pkg>.ini         启动器配置（PAL 运行期读取）
│   │   │   │   └── Custom.nsh        NSIS 钩子源码（构建期编译进 exe）
│   │   │   └── appicon*.ico          图标
│   │   └── DefaultData/              首次运行的默认数据模板
│   ├── docs/ .github/ src/           文档、CI、启动器源码说明
│   └── （迁移后 dist/ 已不存在，见下）
├── _shared/                          ③ 工具链（入库，参数化通用版）
│
└── 产品根（默认 D:\Portapps，仓库外，不入库）
    └── <Pkg>/                        ② 可运行产物
        ├── <Pkg>.exe                 编译好的 PAL 启动器
        ├── update.py                 本包更新脚本（自包含，可随包拷走）
        ├── App/
        │   ├── AppInfo/              运行期读取的配置副本
        │   └── <程序目录>/           真正的第三方程序（不入库）
        ├── Data/                     用户数据（gitignore）
        └── Other/Source/             NSIS 源码副本（开源合规要求）
```

**2026-10-19 迁移事实**：② 可运行产物已从仓库内 `<Pkg>/dist/<Pkg>/`
整体迁到产品根 `<产品根>/<Pkg>/`（默认 `D:\Portapps`）。59.12 GB /
598,293 个文件，同卷原子 `os.rename`（零拷贝、零额外空间），迁移前后
逐文件 SHA-256 全等校验，工具与记录见 `_shared/tools/migrate_dist.py`
与迁移报告。

### 1.1 产品根路径的唯一解析处：`_shared/_paths.py`

所有工具**不再**写 `<Pkg>/dist/<Pkg>` 这类硬编码，一律调
`product_dir(pkg)` / `product_root()`。解析顺序（先命中先用）：

1. 环境变量 `PORTAPPS_ROOT`（或别名 `PORTABLEAPPS_PRODUCT_ROOT`）
2. `_shared/portapps_root.txt` 第一行非注释内容
3. 内置默认 `D:\Portapps`
4. **回退**：仓库内 `<Pkg>/dist/<Pkg>`（未迁移的老布局）

第 4 条保证两个状态零配置自动切换：CI 全新克隆（无 D:\Portapps）时
自动回退老布局，本机装配后自动切新布局。

> ⚠️ 命名冲突警告：旧工具用 `PORTABLEAPPS_ROOT` 表示**仓库根**，
> 产品根故意改用 `PORTAPPS_ROOT`，两个含义不打架。

> `update.py` 由 `_shared/tools/gen_update_strategies.py` 生成，
> 引擎代码**内联**（不 import `_shared/`）—— 因为这个目录常被整个拷走，
> 那时 `_shared/` 不在旁边。迁移后它位于仓库外，靠
> `PORTABLEAPPS_REPO` 环境变量或向上探测定位仓库；找不到就退到临时目录，
> 脚本永远能跑。详见
> [`更新策略报告`](reports/更新策略报告-20261018.md)。

> ⚠️ `portableapps/App/<程序>/` 是**空/不存在**的——程序只在产品树里。
> 任何"按源树路径检查 exe 是否存在"的脚本都会 100% 误报。

### 1.2 包目录下**只放包自己的东西**

构建/测试脚本**不进包目录**，一律放 `_shared/scripts/`（详见
[`_shared/scripts/README.md`](../_shared/scripts/README.md)）。

```
✅ <Pkg>Portable/    只放：portableapps/  docs/  src/  .github/  开源元数据
❌ <Pkg>Portable/scripts/   曾经每个包复制一份 build-portable.py 等
❌ <Pkg>Portable/tests/     曾经每个包复制一份 test_structure.py
❌ <Pkg>Portable/_制作素材/ 制作期取证快照（卸载程序、监控日志，含第三方二进制）
❌ <Pkg>Portable/evidence/  同上，只是命名不同
```

**为什么**：脚手架曾给 39 个包各复制一份脚本，实测
`toolchain.py` 39 份 hash 全同、`package-paf.py` 36 份全同、
`build-portable.py` 39 份差异**只有两行**（docstring 包名 + `PKG` 常量）。
改一个模板要改 39 处，是最大的维护负担。现已收敛为 1 份参数化通用版。

## 2. PAL 运行机制（三件事必须知道）

### 2.1 配置按 `$BaseName` 定位

PAL 运行期用**启动器 exe 的文件名**拼路径：

```
$EXEDIR\App\AppInfo\Launcher\$BaseName.ini
```

一个包有 N 个 exe 就必须有 N 个同名 ini。WPSOfficePortable 有 5 个 exe
（主 / 文字 / 表格 / 演示 / PDF），当年唯独漏了主入口的 ini，导致主程序打不开。

### 2.2 退出时还原宿主

启动前：备份注册表 → 重定向环境变量 → 建 junction → 运行程序 →
**退出后反向还原并清理**。所以被 `taskkill` 强杀会留下残留
（`RuntimeData/`、宿主 junction），这也是排查时必须"冷启动"的原因。

### 2.3 数据落地靠两条腿

| 机制 | 适用 | 配置段 |
|---|---|---|
| **环境变量重定向** | 走 `SHGetKnownFolderPath` / `%APPDATA%` 的应用 | `[Environment]` |
| **目录/文件搬移** | 硬编码路径、不走环境变量的应用 | `[DirectoriesMove]` `[FilesMove]` |
| **Junction 联接** | 无法搬移、必须留在宿主的目录 | `Custom.nsh` 里手工建 |

本库 39 包的 `[Environment]` 全部把 `APPDATA` / `LOCALAPPDATA` 指向
`%PAL:DataDir%`；`[DirectoriesMove]` 只在 BaiduNetdisk / ReNamer / eDiary 等少数包使用。

## 3. 配置文件字段速查

### `appinfo.ini`

| 段 | 关键字段 | 说明 |
|---|---|---|
| `[Format]` | `Type=PortableApps.comFormat`、`Version=3.9` | 格式声明，**dist 树曾大面积缺失** |
| `[Details]` | `Name` `AppID` `Publisher` `Category` `Description` | 平台菜单显示 |
| `[Version]` | `PackageVersion` | 四段式版本号 |
| `[Control]` | `Start` `ExtractIcon` `Icons` | **决定启动器图标**，路径必须真实存在 |
| `[Installation]` | `RemoveFile=` | 安装时清理 |

### `Launcher/<Pkg>.ini`

| 段 | 关键字段 |
|---|---|
| `[Launch]` | `ProgramExecutable`（相对 App）、`CommandLineArguments`、`WorkingDirectory`、`DirectoryMoveOK`、`SinglePortableAppInstance` |
| `[Environment]` | `APPDATA` `LOCALAPPDATA` `TEMP` `TMP` → `%PAL:DataDir%\...` |
| `[Activate]` | `Registry=true` |
| `[RegistryKeys]` | 需要备份/还原的注册表键 |
| `[DirectoriesMove]` / `[FilesMove]` | 宿主路径 ↔ 包内路径 |

### `Custom.nsh`（NSIS 钩子）

钩子宏名**必须**是 `Custom.nsh_<阶段>`（见 `Segments.nsh` L54），
写成 `CustomPreExec` / `CustomInit` 会**静默失效**——这是最阴的一类 bug。

头部注释里沉淀的硬约束（摘抄自 QQPortable）：

1. 文件必须 UTF-8 **无 BOM**（带 BOM 会报 `Invalid command`）；
2. 只能放 `App\AppInfo\Launcher\` 且名字恰为 `Custom.nsh`；
3. `$INSTDIR` 在 PAL 启动器中**未初始化**（展开为空），一律用 `$EXEDIR` 运行时拼接；
4. 拆 junction 只能 `rmdir`（**不带 /s**），带 `/s` 会删穿联接、误删 Data；
5. 绝不联接共享/他软件目录；
6. NSIS 的 `$APPDATA` / `$LOCALAPPDATA` / `$DOCUMENTS` 常量读注册表 Shell Folders，
   **不受** PAL 改的进程环境影响；
7. `robocopy` 合并宿主残留必须带 `/XJ`，否则会把他包 Data 经联接复制进来；
8. 接管已存在的 junction 前必须做三路探针判定（详见 [04 · 避坑手册 §1.2](04-避坑手册.md)）。

## 4. 编码规范（血泪）

| 文件 | 编码 | 原因 |
|---|---|---|
| `Custom.nsh` | UTF-8 **无 BOM** | 带 BOM → `Invalid command` |
| `Launcher/*.ini`（含中文路径） | **UTF-16LE** | UTF-8 会被 NSIS 按 ANSI 解 → 路径乱码 → 启动失败（[实证矩阵](04-避坑手册.md#14--含中文路径的-launcher-iniutf-8-会直接挂本轮实证矩阵)） |
| `appinfo.ini` | UTF-8（无 BOM 亦可） | 不参与启动路径解析，36 个含中文描述的包已实证 |

**结论：`Custom.nsh` 与 launcher ini 的编码要求相反，不要一起"统一"。**

## 5. 包内开源脚手架

每个包应包含（本库多数已齐备）：

```
LICENSE  README.md  CHANGELOG.md  CONTRIBUTING.md
CODE_OF_CONDUCT.md  SECURITY.md  THIRD_PARTY_NOTICES.md
.gitignore  .editorconfig  .gitattributes
.github/    ISSUE_TEMPLATE / PR_TEMPLATE / workflows
docs/       BUILD.md  PORTABLE.md  RELEASE.md
```

`THIRD_PARTY_NOTICES.md` 尤其重要：明确声明第三方软件的权利归属，
是"仓库开源但不分发第三方二进制"这一模式的合规基石。
