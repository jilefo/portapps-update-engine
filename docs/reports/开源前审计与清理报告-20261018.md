## 6. dist → `<PORTAPPS>` 迁移（步骤 4）—— **已于 2026-10-19 执行完成**

> **本节为 2026-10-18 的决策记录（保留原样以备追溯）。执行结果见**
> **[`dist迁移记录与校验报告-20261019.md`](dist迁移记录与校验报告-20261019.md)**：
> 38/39 包 PASS（559,349 文件 / 61.28 GB，前后逐文件 SHA-256 全等），
> `WorkBuddyPortable` 因宿主进程占用延后补迁。
>
> 当时卡住的 §6.2（`update.py` 三级上溯）与 §6.3（更新脚本放 dist 内的约定冲突）
> 的解法：① `update.py` 改为**探测式**定位仓库（`PORTABLEAPPS_REPO` 环境变量 →
> 逐级上溯找 `_shared/scripts` + `_shared/update` → 退临时目录），不再数层级；
> ② 采用**生成器即配方**——仓库只留 `_shared/configs/<Pkg>.yaml` + 生成器，
> `update.py` 作为生成物随产品树搬到仓库外，随时可一键重生成。

### 6.1 事实

| 项 | 数值 |
|---|---|
| `dist/` 总体积 | 59.12 GB |
| `dist/` 文件数 | 598,293 |
| 其中被 git 跟踪 | **40 个文件**（39 × `update.py` + 1 × `version.json`） |
| 目标盘可用空间 | D: 约 32 GB（**无法做全量备份**） |
| 迁移性质 | 同盘目录 rename 到 `<PORTAPPS>`，不消耗额外空间 |

### 6.2 硬冲突：`update.py` 的路径推导

被跟踪的 `update.py` 位于 `<Repo>/<Pkg>/dist/<Pkg>/update.py`，
其路径推导写死了三级上溯：

```python
HERE       = Path(__file__).resolve().parent      # <Repo>/<Pkg>/dist/<Pkg>
PKG_ROOT   = HERE.parents[1]                      # <Repo>/<Pkg>
REPO_ROOT  = HERE.parents[2]                      # <Repo>（_shared/ 所在）
```

`REPO_ROOT` 被用于两处：

1. `REPO_ROOT/_shared/update/_cache|_backups` —— 更新缓存与回滚备份
2. `REPO_ROOT/_shared/scripts/test_structure.py` —— 更新后自检

迁移到 `<PORTAPPS>\<Pkg>\update.py` 后，`REPO_ROOT` 将算出盘根，
`_shared` 不存在 → 落到 `%TEMP%` 回退分支（缓存可忍，**备份位置漂移不可忍**），
`test_structure.py` 调用直接失败。

### 6.3 与既有约定冲突

用户此前的明确要求是「**更新脚本放到 dist 里的便携目录里，每一个项目单独一个更新脚本**」。
而 git 只能跟踪**仓库内**文件。dist 整体迁出后，`update.py` 若要继续被跟踪，
其在仓库中的位置必须改变。

**这两个要求无法同时按原样满足，必须选一个折中。** 已按"先审计、后变更"原则暂停，待决策。
