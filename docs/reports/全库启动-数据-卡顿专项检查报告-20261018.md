## 1. 启动异常

### 1.1 ★ WPSOfficePortable：五个入口全部没有 Custom.nsh（已修）

上一轮「自愈钩子」全库铺开时统计是 76 份 Custom.nsh —— 但那是**有 Custom.nsh 的包**的
两份（dist + source）。WPS 是唯一一个两棵树都没有 Custom.nsh 的包，于是它的
**5 个启动入口**（WPSOffice / Writer / Spreadsheets / Presentation / wpsPDF）
全部没有自愈钩子，异常退出后会命中 §1.6 的「PAL 拒绝启动」分支。

已修：
- 为 WPS 双树各补一份**最小** Custom.nsh（只含自愈钩子，不动原有的环境变量重定向与
  注册表还原逻辑，改动面最小）
- `build_launcher.py` 原来只能产出「包名同名」的 1 个 exe，加了 AppID 覆盖参数后
  重编了全部 5 个入口（各 476 KB）

### 1.2 QQ / QQNT / TIM 的 junction 互斥：源码实证「会自动接管」，不是缺陷

宿主上同时存在 QQPortable 与 QQNTPortable 各自留下的 junction（例如
`%APPDATA%\Tencent\QQ` 指向 QQNT 的 Data）。直觉上会担心「另一包启动被永久阻断」。

逐行核了 `NP_JunctionProbe` 的返回码约定，**结论是设计已经覆盖**：

| 返回码 | 含义 | 行为 |
|---|---|---|
| 0 | 联接已指向本包 Data（崩溃残留） | 直接接管 |
| 3 | 目标已失效，**或**目标是兄弟包的 Data 但**兄弟包进程没在跑** | 拆链重建（指向本包 Data） |
| 1 | 兄弟包**正在运行** | 弹窗中止（正确行为） |
| 2 | 取不到联接目标 | 中止 |

所以陈旧联接会自动接管，不会永久阻断。**这条是靠读源码排除的，不是靠猜。**

### 1.3 静态层面：78 树次 ERROR 0

```
审计 78 个包 —— ERROR 0 条 / WARN 106 条
```
覆盖：入口 exe 与 `Launcher\<BaseName>.ini` 配对、`ProgramExecutable` 真实存在、
`APPDATA`/`LOCALAPPDATA`/`TEMP`/`TMP` 重定向、Data 目录、App 程序目录内是否混入数据目录、
`Custom.nsh` 编码与自愈钩子。

> 中途修正过一次判据：最初把 ini 里的**中文注释**也当成「非 ASCII 键值」报了 46 条
> ERROR，实测这些包全部正常启动 —— 判据改成「只看非注释行的键值」后归零。
> 教训：判据本身会产出假结论（与手册 §6.1 同源）。

## 2. 数据保存不对

### 2.1 ★★ 根因：Electron / VSCode 系有两条落盘路径，环境变量只管得住一条

这是本次最重要的发现。

| 落盘位置 | 应用取路径的方式 | 改 `%APPDATA%` 环境变量 |
|---|---|---|
| `%APPDATA%\<Vendor>` | `SHGetKnownFolderPath(FOLDERID_RoamingAppData)` | **无效**，它不读环境变量 |
| `%USERPROFILE%\.<name>` | Node `os.homedir()` / Electron `app.getPath('home')` | 也只能靠 `USERPROFILE` |

实测（探针逐个真实启动，退出后复查宿主）：

- 退出后仍是**真实目录**（=确凿泄漏）：
  - `~/.trae-cn` **102.9 MB**（运行时 `builtin`、`extensions` 被改写）
  - `~/.ai_completion` **4.8 MB**（`.ripgrep` 被改写）
- 历史累积的真实目录（按最新写入时间排序）：
  `.codeartsdoer` 1209 MB、`.codearts` 220 MB、`.cherrystudio` 281 MB、
  `.codearts-doer-for-coding` 150 MB、`.codebuddy` 52 MB、`.kukuai` 39 MB、
  `.codebuddycn` 58 MB、`.cursor` 1.5 MB、`WorkBuddy\` 26 MB

> 注意：`%APPDATA%\CherryStudio`、`%APPDATA%\codearts`、`%APPDATA%\catpaw-moon`、
> `%APPDATA%\MiniMax`、`%APPDATA%\Tencent\TIM` 等在探针里也曾被报为「新增」，
> 但复查确认**退出后它们是 junction**（已被接管），不是泄漏。
> 判据必须是「退出后宿主上仍以真实目录存在」，只看"有没有变化"会误判。

### 2.2 已修：7 个点目录 junction 接管

`_shared/tools/fix_dot_home_dirs.py`，沿用仓库既有语义（宿主真实目录先 robocopy 进
Data 再移除，**不丢数据**；已是 junction 则不抢不拆；退出只 `rmdir` 不带 `/s`）：

| 包 | 接管后的宿主 junction | 目标 |
|---|---|---|
| TraeCNPortable | `~/.trae-cn`、`~/.ai_completion` | `Data\settings\user\...` |
| CherryStudioPortable | `~/.cherrystudio` | 同上 |
| CodeArtsPortable | `~/.codearts`、`~/.codeartsdoer`、`~/.codearts-doer-for-coding` | 同上 |
| KukuAIPortable | `~/.kukuai` | 同上 |
| CursorPortable | `~/.cursor` | 同上 |

验收（修复后复测）：7 个点目录全部变为 junction，宿主侧不再是真实目录；
CursorPortable 优雅退出后 junction 已自动拆除（证明收尾链路通）。

### 2.3 刻意没做的两个（有破坏性，留手工）

`~/.workbuddy`、`~/.codebuddy` —— **本机宿主实例正在使用**，一旦接管会直接打断
当前会话。这两个只能在宿主实例关闭后手工决定。

### 2.4 ZoomPortable 缺 TEMP/TMP（已修）

全库 39 包里唯一缺 `TEMP`/`TMP` 重定向的包，临时文件/崩溃转储会直接落宿主 `%TEMP%`。
双树均已补齐。

### 2.5 遗留：`%TEMP%\<Pkg>Temp` 与 `nsm*.tmp`

实测每个包启动都会在**宿主** `%TEMP%` 下建 `<Pkg>Temp` 和 `nsXXXX.tmp`。
这是**启动器进程自身**建的（PAL 只把环境变量改给子进程，启动器本人仍用宿主 TEMP），
属 PAL 固有行为，且都是临时文件，不列为缺陷。

另：`%LOCALAPPDATA%\Temp\nope\`（约 1.7 GB，内含 `dist\`、`portableapps\` 结构）
是**构建期遗留的临时副本**，不是软件运行时产生的，建议清理（未在本轮自动删除）。

## 3. 卡顿

### 3.1 硬数据

本机实测 6 次平均：

| 启动一个子进程 | 单次耗时 |
|---|---|
| `powershell -NoProfile -ExecutionPolicy Bypass -File x.ps1` | **1.37 s** |
| `cmd /c echo x` | **0.082 s** |

差 **16 倍**。

### 3.2 全库实测排行（修复前，17 个高风险单元）

| 单元 | 首子进程耗时 | 子进程调用数 | 折算 PowerShell 成本 |
|---|---|---|---|
| **QQPortable** | 20.9 s | 24 | ≈16 s |
| **QQNTPortable** | 14.1 s | 16 | ≈11 s |
| TIMPortable | 11.6 s | 13 | ≈9 s |
| CursorPortable | 8.9 s | 6 | ≈4 s |
| CodeBuddyCNPortable | 9.2 s | 6 | ≈4 s |
| TraeCNPortable | 7.6 s | 6 | ≈4 s |
| MiaoshouPortable / MiniMaxCodePortable / ZoomPortable | 6.3 s | 4 | ≈2.7 s |
| CherryStudio / CodeArts / KukuAI 等 | 1.0~3.3 s | 0~2 | ≈0 |

### 3.3 已修：junction 判定改成 NSIS 原生快速路径

`_shared/tools/opt_fast_junction_probe.py`（套用到 QQ / QQNT / TIM / Weixin / WXWork 5 包）：

1. 在 TARGET 里写探针文件 → HOST 下能看见 → **0**（本包所有）
2. 否则试探 HOST 可否写入 → 写不进去 → **3**（联接失效）
3. 只有「联接存活但不属本包」才回退 PowerShell 精判

快速路径**不读包名、不起子进程**，所以对任何含 `NP_JunctionProbe` 的包都无损适用。

效果：QQPortable **20.9 s → 1.2 s**，PowerShell **24 → 1** 次。

### 3.4 一次性迁移成本（不是回归）

首轮跑 TraeCN / CodeArts 时耗时上涨（TraeCN 19.3 s、CodeArts 20.3 s），原因是
`SJ_Create` 首次要把宿主上已存在的点目录 **robocopy 进 Data**（`.codeartsdoer` 就有
1.2 GB）。第二轮回落到 5.2 s / 7.7 s —— 确认是**一次性**迁移，之后宿主已是 junction，
直接跳过拷贝。

副作用：这几个包的 `Data\` 体积变大（CodeArts ≈1.3 GB、Cursor 614 MB、KukuAI 338 MB、
CherryStudio 297 MB、TraeCN 110 MB）。这是把**原本泄漏在宿主的数据搬回包内**，
磁盘总量不变，符合"便携包自带数据"的预期。

### 3.5 还没做的优化（下一轮）

- 收尾耗时：探针里多数包 `t_exit` 撞到 20 s 上限，是因为 **WM_CLOSE 关不掉**
  （Electron 系多最小化到托盘），只能强杀。真实用户手动关闭不受影响，
  但意味着「被强杀 → junction 残留」，靠下次启动的 Scavenge/自愈接管。
- TraeCN 仍剩余 3 次 PowerShell（`count` / `kill` / 自愈 `alive`），可继续合并。
