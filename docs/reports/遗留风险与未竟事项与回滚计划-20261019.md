## 3. 处置手册（照抄即可）

### 3.1 改作者身份（推送前必做）

```bash
git config user.name  "<你的名字>"
git config user.email "<你的邮箱>"
# 只改最后一个提交：
git commit --amend --reset-author --no-edit
# 要改全部 4 个（推荐，避免历史里留占位符）：
git rebase --root --exec 'git commit --amend --reset-author --no-edit'
git log --format='%h %an <%ae>'      # 复查
```

> 警告：`--amend` / `rebase` 会重写提交哈希。**只在还没推送过时做**；

## 4. 回滚计划

### 4.0 先记住这三条

1. **rename 不复制、不删除任何文件内容**——它是同卷元数据操作，原子、零拷贝。
   所以"迁移出问题"最坏情况是路径指错，**数据本身不会少**。
2. **删 junction 用 `rmdir`（不带 `/s`）**——只摘链接，不碰目标数据。
   带 `/s` 会删穿目标，那是真正的事故。
3. **回滚前先量空间**：D 盘当前可用 30.0 GB，逐个大包回滚不需要额外空间，
   但**整包复制式回滚会撑爆**（R3）。本节全部用 rename，不用复制。

### 4.1 单包回滚

```bash
# 1) 确认当前位置
python _shared/tools/migrate_dist.py status --pkg <Pkg> 2>/dev/null || \
python _shared/tools/migrate_dist.py status

# 2) 逆 rename（同卷、原子、瞬时）
#    D:\Portapps\<Pkg>  →  <Repo>/<Pkg>/dist/<Pkg>
#    逐包逆操作即可，工具没有提供反向子命令，用系统命令：
cmd /c move "D:\Portapps\<Pkg>" "<Repo>\<Pkg>\dist\<Pkg>"

# 3) 把该包的包内 junction 按旧路径重建
#    清单在 _shared/migration/pre/<Pkg>.json 的 junctions[].rel / target
#    删除用 rmdir（不带 /s），重建用 mklink /J
cmd /c rmdir "<junction 路径>"
cmd /c mklink /J "<junction 路径>" "<旧目标路径>"

# 4) 校验
python _shared/tools/migrate_dist.py verify --pkg <Pkg>
```

> junction 清单可能随 PAL 运行时起落，以 `pre/<Pkg>.json` 为准（迁移那一刻的快照）。

### 4.2 全量回滚

按 4.1 逐包逆 rename，顺序**建议从小到大**（先把小包挪回去腾出操作余地，
也便于中途发现问题立刻停手）：

```
eDiary 32MiB → FSCapture 32MiB → ReNamer 17MiB → ... → FoxitPDF 3,943MiB
```

每包做完立即 `verify --pkg`，不要攒到最后一起验——
**攒着验等于把 39 次机会合成 1 次机会**。

### 4.3 校验依据（都有留档）

| 依据 | 位置 |
|---|---|
| 逐包前/后文件数、字节数、junction 数 | `_shared/migration/migration_log.jsonl` |
| 逐文件 (相对路径, 大小, SHA-256) 快照 | `_shared/migration/pre/<Pkg>.json` |
| 逐包执行记录 | ④ §3.2 逐包表 |

### 4.4 只想修 junction、不想回滚

```bash
python _shared/tools/migrate_dist.py repoint --pkg <Pkg>        # 预览
python _shared/tools/migrate_dist.py repoint --pkg <Pkg> --yes   # 执行
```

幂等：目标已正确就跳过；新建前会**先校验目标真实存在**，
`mklink` 之后**回读目标与预期比对**，不一致就回滚到旧目标。
（这条是踩过"mklink 对不存在的目标也返回 0"才加的，见 ④ §5.1）

**数据没丢、结构对、校验过**。真正还没做的只有三件事：
**改 git 身份**（R1，推送前必做）、**实推一次**（R6/3b，整仓级与包级各一次）。

> **本轮（交付物 ⑥）追加的教训**：此前 34 份包级 `release.yml` 产出 **0 个附件**
> 而流水线全绿。三处缺陷（格式写错 / 开关跳过打包 / 无产物时 WARN+return 0）
> 彼此掩盖。根因不是粗心，而是**维护方式**——workflow 由 scaffold 复制生成、
> 之后只靠文本替换修路径，而文本替换能改字符串、改不了语义。
> 现在改为生成器 + 运行时解析，并把一致性门禁接进 CI（含 YAML 解析，
> 且带负样本验证过门禁真的会红）。
