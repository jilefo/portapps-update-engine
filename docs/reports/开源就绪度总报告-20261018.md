## 2. 本轮（1.1.0）新发现并修复的缺陷

### 2.1 ★ `Custom.nsh` 带 UTF-8 BOM（新维度翻出的旧账）

| 包 | 文件 | 树 |
|---|---|---|
| BaiduNetdiskPortable | `App\AppInfo\Launcher\Custom.nsh` | dist + portableapps |
| CodeArtsAgentPortable | `App\AppInfo\Launcher\Custom.nsh` | dist + portableapps |

共 4 个文件。BOM 会让 NSIS 把 `EF BB BF` 当 token 解析 → `Invalid command`。

- 修复：新增 `_shared/tools/fix_strip_bom.py`，备份 `.bak-bom-<时间戳>` 后字节级剥离
- 复核：残留 BOM 0 个
- 回归冒烟：`BaiduNetdiskPortable` PASS（子进程 t+1.42s，Data 新写 73，弹窗 0）、
  `CodeArtsAgentPortable` PASS（t+0.72s，Data 新写 78，弹窗 0）
- **为什么之前没发现**：原 `check_custom_nsh.py` 只查引号/裸变量/管道病态，
  没查 BOM。说明每新增一个自检维度都可能翻出旧账。

### 2.2 工具自身缺陷（会被开源放大，必须修）

| 脚本 | 缺陷 | 修复 |
|---|---|---|
| `check_custom_nsh.py` | 包目录上溯层数少一级，38 个包全输出 `[dist]` | 改为上溯 6 层 |
| `smoke_real.py` | 未登记进程名的包直接 `KeyError` 崩溃 | 新增 `targets_of()` 兜底按包名推测 |

### 2.3 字段认知纠错（避免 CI 误报）

`[Control]` 段里**没有** `Name`（它是 `Start` / `ExtractIcon` / `Icons`），
包名在 `[Details]Name` 或 `[AppInfo]Name`。最初按错误假设写的检查项让 39 个包
全部误报 FAIL，已按真实 PAL 字段修正。
