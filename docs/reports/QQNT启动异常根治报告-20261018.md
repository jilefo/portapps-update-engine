# QQNT 启动异常根治报告

日期：2026-10-18
触发：用户反馈「QQNTPortable 一直不行啊，启动异常」
结论：**已定位、已根治、已全库推广**。根因不在 QQ 本身，而在 PortableApps.com
Launcher（PAL）的一段硬编码分支。

---

## 1. 现象还原

启动 `QQNTPortable.exe`，弹出对话框：

```
QQNT Portable (PortableApps.com Launcher)

QQNT Portable did not close properly last time it was run and will now
clean up. Please then start QQNT Portable again manually.

                                  [确定]
```

点「确定」后**什么都没发生** —— QQ 根本没启动。
观测：启动器进程存活 75 秒，始终只有它自己，没有任何 `QQ.exe` 子进程。

用户视角就是「点开没反应 / 一直打不开」，且不知道还要再点一次 —— 与
「一直不行」完全吻合。

排查开始时抓到的现场证据（此时无任何 QQ 进程）：

| 宿主路径 | 状态 |
|---|---|
| `%APPDATA%\QQ` | junction → QQNT `Data\settings\QQ`（陈旧残留） |
| `%APPDATA%\Tencent\QQNT` | junction → QQNT `Data\settings\Tencent\QQNT`（陈旧残留） |
| `%APPDATA%\Tencent\QQ` | 已拆 |
| `Documents\Tencent Files` | 已拆 |
| `%ProgramData%\Tencent\qimei` | 已拆 |

即上一轮**没有干净收尾**，junction 只拆了一部分。

---

## 2. 根因（PAL 源码实证）

工具链里有 PAL 完整源码：
`_shared\toolchain\PortableApps.comLauncher\Other\Source\`

### 2.1 启动主流程

```nsis
; PortableApps.comLauncher.nsi
Section
    Call Init                       ; Function Init 第 1 段就是 ${RunSegment} Custom
    ...互斥检查（AlreadyStarting / AlreadyStopping）...

    ${IfNot} ${FileExists} $DataDirectory\PortableApps.comLauncherRuntimeData-$BaseName.ini
    ${OrIf} $SecondaryLaunch == true
        ...
        Call Execute                ; ← 正常启动的唯一路径
    ${Else}
        MessageBox MB_ICONSTOP $(LauncherCrashCleanup)   ; ← L421
        ; 注释原文：After doing Post, we don't do restart automatically ...
    ${EndIf}
    ${If} $WaitForProgram != false
        ${CallPS} Post -            ; 直接收尾
    ${EndIf}
    Call Unload
SectionEnd
```

**只要 `Data\PortableApps.comLauncherRuntimeData-<BaseName>.ini` 存在，
PAL 就只弹一个框然后收尾，永远不调用 `Execute`。**

`LauncherCrashCleanup` 的语言串（`LangStringDecl.nsh` L36）就是上面那段英文。

### 2.2 ini 什么时候被删

```nsis
; Segments\Core.nsh  ${SegmentUnload}  L113
Delete $DataDirectory\PortableApps.comLauncherRuntimeData-$BaseName.ini
```

**只在 PAL 正常收尾时删除。** 任何强杀进程 / 断电 / 崩溃 / 上一轮收尾卡死，
都会把它留在 `Data\` 下，于是下次启动必然命中 Else 分支。

### 2.3 ini 里没有开关

`Launcher\*.ini` 支持的所有 `[Launch]` 配置项里，**没有任何一项能关掉这个行为**。
`SingleAppInstance` / `SinglePortableAppInstance` 管的是另一套互斥，与此无关。

---

## 3. 为什么之前一直没发现（关键）

冒烟脚本里早就有这段：

```python
def pre_clean_rt(base):
    for pat in ("PortableApps.comLauncherRuntimeData-*.ini", "RuntimeData.ini"):
        for f in glob.glob(os.path.join(d, pat)):
            os.remove(f)
```

`smoke_real.py` / `smoke_all_projects.py` 在启动前会**主动删掉这个 ini**，
于是冒烟永远 PASS。工具注释里其实写着：

> 启动前预清 RuntimeData ini（否则 PAL 走 CrashCleanup 分支永不 Exec —— 自锁）

**症状在工具层被绕过了，产品层从未修。**
本次是靠「不做任何预清理」的 3 轮冷启动 + 抓对话框文本才复现出来的。

## 4. 排除项（都验证过，不是原因）

| 怀疑点 | 结论 |
|---|---|
| `ProgramExecutable` 路径错 | `App\QQNT\QQ.exe` 存在，路径正确 |
| 版本目录缺失 | `versions\config.json` `curVersion=9.9.36-53644`，目录存在且完整 |
| QQNT 自身崩溃 | `app_launcher-20261018.log` 每次都打印「成功的分割线」，主进程已加载 `application.asar`；Crashpad reports 目录为空 |
| 宿主 junction 互斥弹框 | 弹的是 CrashCleanup 框，不是「便携启动中止」 |
| 数据不落盘 | `Data\documents\Tencent Files\nt_qq\...` 有 prelogin 日志，落地正常 |
| 正常生命周期有问题 | 3 轮冷启动（启动→关窗→收尾）全部 PASS，t+12s 干净退出、junction 6 条全拆、零残留 |

**结论**：正常生命周期是健康的；故障只在「上一轮异常终止」之后出现。

## 5. 修法

新增 `Custom.nsh_Init` —— 它是 PAL `Function Init` 的第 1 段，
**早于** §2.1 那个 `FileExists` 判断：

```nsis
!macro Custom.nsh_Init
  FindFirst $8 $9 "$EXEDIR\Data\PortableApps.comLauncherRuntimeData-*.ini"
  StrCmp $8 "" _np_init_done        ; 没有残留 → 零开销跳过
  FindClose $8
  !insertmacro NP_WriteHelpersInit  ; 写精简 ps1
  System::Call 'kernel32::GetCurrentProcessId() i.r6'
  nsExec::ExecToStack 'powershell ... .np-helpers.ps1 alive "$6" "" "" "$EXEDIR"'
  Pop $8
  Pop $9
  StrCmp $8 "0" 0 _np_init_done     ; 包内还有别的存活进程 → 不动
  Delete "$EXEDIR\Data\PortableApps.comLauncherRuntimeData-*.ini"
  _np_init_done:
!macroend
```

三条设计约束：

1. **只在本包确认无存活实例时才删。** 有实例则完全保持 PAL 原有行为 ——
   不绕过"已在运行"保护，也不破坏 junction 互斥（不会出现两个实例抢同一份 Data）。
2. **Init 阶段 `$DataDirectory` 尚未赋值**（`Variables` 段才 `StrCpy`），
   路径一律用 `$EXEDIR\Data`。
3. **无残留时零开销** —— 用 `FindFirst` 先探，正常路径不启动 pwsh，
   不增加启动耗时。

## 6. 影响面与落地

这不是 QQNT 独有的问题，是 PAL 的通用行为：**全库 38/39 个包都会中招**。

| 步骤 | 结果 |
|---|---|
| `fix_launcher_rtdata.py --apply` | 写入 76 个 `Custom.nsh`（`portableapps/` + `dist/` 双树），编码 76/76 UTF-8 无 BOM |
| 重编启动器 | 38/39 成功 |
| `WorkBuddyPortable` | exe 被运行中的便携实例占用（`Can't open output file`），**未重编**；`Custom.nsh` 已注入，关掉实例后补编即可 |

> ⚠️ `Custom.nsh` 是**编译进 exe** 的，只改文件不重编等于没改。
