## 0. 重要前置说明：白天早些时候的判定为何作废（污染误判翻案）

v3 之前的冒烟结果（31 PASS / 1 WARN / 8 FAIL，含 AiPyPro、WPS 三分体、CherryStudio 等）**判定口径被沙箱污染，全部作废**：

| ① | NSIS 把内联脚本里的裸 `$l/$t/$p/$own/$lt/k/v/$root/$_.PSPath` 当未声明变量吞掉（要 `$$` 转义） | 编译 warning `unknown variable/constant`，ps 脚本被改写后 ParserError |

### 2.9 QQPortable / TIMPortable 打不开：三重根因链（用户报告复现）

用户报告 QQPortable、TIMPortable、WPSOfficePortable、WeixinPortable 打不开。逐一复现后确认两个真 FAIL（QQ/TIM）+ 两个已修（WPS 主、微信本次复测 PASS）。**QQ/TIM 的病因是三重叠加**：

**根因①（WPS 主入口）**：`WPSOfficePortable.ini` 缺失——PAL 运行期按 `$BaseName` 拼 `App\AppInfo\Launcher\<BaseName>.ini`，5 个 exe 中唯独主 exe 的 ini 没生成（分体 ini 都在），双击即报 `is missing [Launch]:ProgramExecutable`。此前冒烟只测 4 个分体漏了主入口。**修复**：按分体模板补齐主 ini（ProgramExecutable=office6\wpsoffice.exe，UTF-8 BOM），复测 wpsoffice.exe@0.72s PASS。

**根因②（宿主 junction 残留未清全）**：QQPortable 用 13 条宿主 junction，上一轮 cleanup 只拆了 8 条（且 `Documents` 被重定向到 `%USERPROFILE%\Documents`，按 `%USERPROFILE%` 扫根本扫不到）。QQNT 冷启动残留的 `Tencent\libsdk/beacon/IM/Logs/Common/TXSSO/QQPCMGR/QQTempSys`、`Tencent Files`（重定向盘）等全在 → QQ/TIM 探针判 foreign → 弹「便携启动中止」。**修复**：本轮扫描范围扩到全部宿主根（含注册表解析的真实 Documents），清掉 16 条残留。

**根因③（fix5 补丁双重事故——最隐蔽）**：给探针加「他包进程探活」时连踩两坑——
1. **死代码**：注释写「插入 `exit 1}` 之前」，代码却 `replace(ANCHOR, ANCHOR + NEW_LINES)` 插到了**之后**——probe 模式第 63 行 `exit 1}` 已关闭分支，探活 9 行永不执行；
2. **游离花括号**：挪正后块尾变成 `...exit 3}` + 残留的 `exit 1}`——后者闭合不了任何块，**PowerShell ParserError，而 `-File` 遇解析错误的退出码恰好是 1**，与探针语义 exit 1（他包真在运行）撞车 → 启动器对所有外来 junction 一律弹中止框。

 fix6（挪位置）+ fix7（删游离 `exit 1}`，probe 块以 `exit 3}` 收尾）后三包重编，`[Parser]::ParseFile` 静态验证 PARSE OK。

### 2.10 WPS 五入口「启动后都是WPS文字」：首页壳机制实锤与 /nostartpage 修复（用户报告复现）

用户报告：WriterPortable / wpsPDFPortable / WPSOfficePortable / PresentationPortable 图标不对，且 Writer / wpsPDF / WPSOffice 启动后都是「WPS文字」。

**图标结论（构建无缺陷）**：用 `scripts\probe_icons.py`（ExtractIconExW→DrawIconEx→GetDIBits 逐像素哈希）+ `scripts\icon_contact_sheet.py`（渲染对照图人工判读）双重验证——**5 个启动器 exe 的内嵌图标全部正确且互不相同**（主入口蓝色 W 徽标 / 文字蓝 W / 表格绿 S / 演示橙 P / PDF 红 P），与各自 `appicon[N].ico` 逐一 MATCH。用户侧「图标不对」的残余解释：① Explorer/任务栏图标缓存未失效（需重建图标缓存或重启 explorer）；② `reports\data\wps_launcher_backup_20261017\` 下还有 5 个 **2021 年旧版启动器**（424KB），若快捷方式误指向备份目录则必然是旧图标。

**启动行为根因（WPS 2023 统一架构「首页壳」）**：用 UI Automation 控件树（`scripts\probe_wps_uia2.py`）实测——**所有组件不带 `/nostartpage` 启动时都先落「首页壳」**：

- 类名规律：`Kx<Wps|Et|Wpp|Pdf>PromeMainWindow`，首页壳含 4 个专属控件 `新建 / 最近 / 打开 / 暂无打开记录`，UI 文本仅 4~5 个；
- 因此 `wps.exe`、`wpsoffice.exe` 无参 → 首页壳（标题「WPS文字」），`et.exe` → 首页壳（标题「WPS表格」但内容是首页仪表盘），`wpp.exe` 同理——**组件选择确实生效（类名不同），但界面都是首页**，这就是「启动后都是WPS文字」的真相；
- 截图像素对比（`capture_wps_states.py`）证实 `wpsoffice.exe` 无参与 `/wps /w` 首屏**逐字节相同**（sha256 一致）——单靠 `/wps /w` 跳不过首页。

**修复（`/nostartpage` 开关，14 组开关穷举后唯一有效）**：`scripts\probe_wps_switches3.py` 穷举 14 种参数组合，唯 `/nostartpage` 能跳过首页壳（3 次重复验证 100% 复现）：首页 4 控件中「打开/最近/暂无打开记录」消失，UI 文本 5→18~20（功能区出现），标题变「WPS 文字 / WPS 表格 / WPS 演示」（注意带空格，与首页壳「WPS文字」区分）。
