# 最终全权托管执行协议（追加到 V3 末尾）

## 1. 授权范围

你被全权授权接管本项目在电脑上的执行工作，范围包括：
1. <旧工作区> 下所有便携软件项目、Work 目录、Logs 目录、构建输出、测试报告和文档。
2. %USERPROFILE%\Downloads 仅用于查找所需安装包和依赖文件。
3. 与本项目直接相关的编译、打包、测试、修复、回归、记录和文档更新。

你不需要反复确认，不需要频繁提问，不需要等待逐步指令。按 V3 任务清单和本协议自动推进，一条龙完成。

## 2. 免打扰与自主决策

1. 用户只负责最终验证成果，不参与中间过程。
2. 遇到普通问题时，自行查资料、自行尝试、自行回滚、自行选择最佳方案。
3. 每批任务最多集中上报一次阻塞，不得零散打扰。
4. 若必须提问，必须附带默认决策和推荐方案，不能只抛问题。
5. 能在本地验证的，不要问；能通过日志和测试判断的，不要问；能自己修复的，不要问。

## 3. 安全边界与备份

1. 只操作项目相关目录，不触碰无关个人文件、系统关键文件和其他项目。
2. 禁止格式化磁盘、删除非项目文件、修改系统安全策略、关闭杀毒软件、修改防火墙、上传敏感数据、付款、注册账号。
3. 高风险操作前必须创建快照、备份或记录回滚方案。
4. 需要管理员权限时，记录原因和影响；不得擅自提升权限或修改系统安全设置。
5. 需要账号、验证码、许可证、付款、人工确认时，标记为阻塞，集中上报。

## 4. 自动化一条龙流程

1. 建立统一测试模板、问题单模板、证据模板和文档模板。
2. 建立自动化检查脚本，至少检查 Data 目录、系统路径残留、注册表差异、进程列表和文件哈希。
3. 解析 <旧工作区>/Logs 中已有安装监控日志，提取 Qoder 系列等项目的安装写入基线。
4. 按 V3 分批计划执行 P0、P1、P2 项目。
5. 每个项目至少覆盖 10 类测试场景，关键场景至少 3 轮回归。
6. 发现问题立即修复，修复后回归验证。
7. 无法修复的问题，输出原因、影响范围、临时替代方案和长期建议。
8. 所有错误、坑点、根因、修复方案和预防措施全部记录在案。
9. 更新 README、便携化说明、构建说明、测试指南、已知问题、更新日志、坑点记录、许可证与第三方组件声明。
10. 每完成一批输出阶段总结，再进入下一批。

## 5. 阻塞与上报格式

只有遇到无法自行推进的问题时才上报，格式固定：
1. 项目名。
2. 问题描述。
3. 已尝试方案。
4. 证据与日志。
5. 影响范围。
6. 建议方案。
7. 默认决策。

上报后继续推进其他不受影响的任务，不得因为单个阻塞停下整批工作。

## 6. 交付与验收

每个项目完成后输出：
1. 项目名。
2. 最终状态：通过、不通过、有条件通过、阻塞。
3. 测试轮次与场景覆盖。
4. 关键证据。
5. 修复项列表。
6. 遗留问题与白名单例外。
7. 文档路径。

最终交付：
1. 18 个便携软件项目修复版。
2. 每个项目的真实测试报告。
3. 统一坑点与解决方案文档。
4. 更新后的 README、便携化说明、构建说明、测试指南、已知问题和更新日志。
5. 最终总结报告，标明每个项目状态。
6. Qoder 系列与监控日志的对比验证结果。

用户只按最终报告和实际运行结果验收，不检查中间过程。

## 7. 完成定义

只有同时满足以下条件，任务才算完成：
1. 18 个项目全部完成至少 10 类场景测试。
2. 所有阻断性问题已修复或明确标记阻塞。
3. 所有问题、坑点、修复方案已记录。
4. 所有项目测试报告已归档。
5. 所有相关文档已更新。
6. 开源便携验收标准全部满足，白名单例外已登记。
7. 最终总结报告已输出，每个项目状态明确。
8. Qoder 系列项目已对照 <旧工作区>/Logs 中的监控日志完成验证。
