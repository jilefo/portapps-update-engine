## 二、exeico — 图标提取

**用途**：从原程序 EXE 中提取图标（.ico），嵌入便携启动器，解决启动器显示默认空白图标的问题。

**前提**：`exeico` 已配置到系统 PATH。

**用法**：

```bat
exeico exe "原程序.exe路径" "输出.ico路径"
```

**要点**：

- 原程序有多个图标变体（不同尺寸 / 状态）时，**优先使用主图标**；
- 提取的图标需嵌入 / 关联到便携启动器 EXE；
- **验收标准**：启动器在文件资源管理器、任务栏、Alt+Tab 三处均显示原程序图标。

**项目封装**：`_analysis` 下已有完整图标流水线，优先复用而非手工调用：

| 脚本 | 职责 |
|------|------|
| `extract_icons.py` / `Extract-Icons.ps1` | 批量从各软件主程序提取 .ico |
| `make_icons.py` | 图标格式 / 尺寸处理 |
| `gen_icon_map.py` → `icon_map.txt` | 建立软件到图标的映射 |
| `check_icons.py` | 校验所有便携启动器图标是否已正确嵌入 |

## 三、PortableApps.com Launcher（PAL）— 启动器编译

**用途**：把 `appinfo.ini` + `launcher.ini` + `Custom.nsh` 编译为便携启动器 EXE。

**工具位置**：`Template Center\PortableApps.comLauncher\`（**仅供人工编译**，自动化分析流程不读取其中文件）。

**目录要求**：便携包必须满足 PAL 标准结构——`App\AppInfo\appinfo.ini`（必需字段齐全）+ `App\AppInfo\Launcher\{软件名}Portable.ini`。

**编译入口**：`makensis`（NSIS 编译器，PAL 基于 NSIS）。

**项目封装**：

- `build_launcher.py` / `build_launcher2.py`：单个便携包的 PAL 构建器，定义 AppInfo 结构要求、appinfo.ini 必需字段与 makensis 编译入口；
- `build_batch3.py` / `build_batch45.py`：批次通用构建器，集中定义多个 VS Code/Electron 系包的构建参数，机器生成配置代替手工编写；
- `build_one.py` / `build_new.py` / `build_librewolf.py`：特定包/新包的构建入口。

**调试版启动器**：PAL 可生成调试版启动器，运行后在 `Data\debug.log` 输出注册表读写、环境变量替换、FileWriteN 命中情况，是排查配置问题的第一手材料。

**重编译时机**：启动器 exe **通常不需要随软件版本更新重新编译**，仅当主程序路径或启动参数变化时才重编。

## 四、PortableApps.com Installer — .paf.exe 打包

**用途**：把测试通过的便携目录打包为 `.paf.exe` 标准分发安装包。

**使用时机**：仅在需要**对外分发**时使用；个人/团队自用保留便携目录及启动器 `.exe` 即可直接使用，无需打包。

## 五、7-Zip — 安装包解包

**用途**：官方无便携包时，从离线安装包中**提取**程序文件，避免安装到系统污染宿主环境。

**典型用法**：

```powershell
# 解包 EXE 安装包到临时目录（多数 NSIS/Inno 安装包可被 7z 直接解开）
7z x "installer.exe" -o"临时提取目录"
```

**要点**：

- 提取到**临时目录**，确认结构后再拷贝进 `App\{软件名}`；
- 优先使用 7z 解包或静默安装到临时目录，**不要直接安装到系统**；
- 安装日志、安装包、提取临时文件**一律不得放入**最终便携包；
- 下载安装包后先校验数字签名与 SHA256。

## 六、Total Uninstall — 安装行为监控

**用途**：监控软件安装全过程，导出**注册表差异**与**文件系统差异**，是九步工作流第 1、2 步的事实来源。

**用法**：

1. 安装前先对系统做一次快照；
2. 通过 Total Uninstall 启动软件安装；
3. 安装完成后再做一次快照，生成差异；
4. 导出"注册表项目"与"文件和文件夹"两类日志（项目根目录各软件目录下的 `.reg` 与 `.txt` 即此类产物，如 `Webex 日志 - 注册表项目.txt`、`Webex 日志 - 文件和文件夹.txt`）。

**要点**：

- 日志是 launcher.ini 的**唯一合法来源**，不得凭猜测编写配置；
- 区分 HKCU / HKLM、用户目录 / 系统目录，据此判定制作等级与路线；
- 发现服务、驱动、Shell 扩展写入时 → 标记不适合便携化；
- 日志属分析原料，**不得放入最终便携包**；
- WPS 等 COM 集成深的软件更新时，必须**重新监控**（注册表键与 COM 组件可能变化）。

## 七、Sandboxie Plus — 沙盒提取与更新方案

**用途**：评估中的**更新维护方案**——在沙盒内静默安装新版本，再提取变更文件覆盖便携目录。

**背景**：Sandboxie Plus 安装程序本身支持"Extract all files to directory for portable use"选项，可以便携模式运行。

**两条更新路径对比（评估中）**：

| 方案 | 流程 | 自动化 | 可靠性 | 维护成本 |
|------|------|--------|--------|----------|
| A：沙盒提取 | 沙盒内静默安装新版 → 提取变更文件 → 覆盖便携目录 | 中 | 待验证（沙盒内文件变更能否可靠导出） | 中 |
| B：离线包解包 | 下载官方离线安装包 → 7z 解包 → 覆盖便携目录 | 高 | 高 | 低 |

**当前倾向**：方案 B 链路更短、可靠性更高；方案 A 仅在官方不提供可解包离线安装包时考虑。**结论待正式评估文档输出**（见 todolist 任务 6）。

**注意**：Sandboxie 是沙盒工具，用沙盒"提取"安装文件是可行思路，但需先确认沙盒内文件变更能被可靠导出，再纳入正式流程。

## 八、项目自有 Python 工具链（_analysis）

`Work\_analysis\` 下的 70+ 个 Python 脚本是项目的自动化核心，按职责分五类：

### 8.1 构建类

| 脚本 | 职责 |
|------|------|
| `build_launcher.py` / `build_launcher2.py` | PAL 启动器构建（AppInfo 校验 + makensis 编译入口） |
| `build_batch3.py` | 第三批 VS Code 系通用构建器（Cursor / Trae CN / CodeBuddy CN / Qoder CN / WorkBuddy 参数集中定义） |
| `build_batch45.py` | 第四、五批通用构建器 |
| `build_one.py` / `build_new.py` / `build_librewolf.py` | 单包 / 新包 / 特定包构建入口 |
| `launcher_wrapper.py` | 生成 `_launcher.bat` 包装层：清除 `ELECTRON_RUN_AS_NODE` 等脏变量、设置 APPDATA/LOCALAPPDATA/TEMP 后启动主程序（Electron 系必需） |
| `write_custom_nsh.py` / `write_electron_nsh.py` / `write_nsexec_nsh.py` | 生成 Custom.nsh（自启/计划任务/后台进程处理） |

### 8.2 验证与测试类（质量闭环）

| 脚本 | 职责 |
|------|------|
| `verify_redirect.py` / `test_redirect.py` | 数据重定向验证：对比启动前后 `Data\` 与宿主 APPDATA/LOCALAPPDATA 的文件变化，判定是否存在宿主写入泄漏 |
| `test_portable.py` / `test_all.py` / `test_pkg.py` | 便携包自动测试：启动、进程存活、`Data\` 增长、宿主残留四项检查 |
| `verify_all.py` / `verify_honest.py` / `verify_layout.py` / `validate_portable.py` | 便携包结构 / 配置完整性校验 |

### 8.3 修复类（历史踩坑产物）

`fix_ini.py`、`fix_env.py`、`fix_launcher_keys.py`、`fix_launcher_values.py`、`fix_missing.py`、`fix_patch_vars.py`、`fix_custom_nsh.py`、`fix_wemeet_bat.py`、`junction_fix.py` 等——launcher.ini 键名/取值/变量引用、环境变量、目录联接等历史问题的修复脚本。**同类问题先用通用构建器重新生成，再考虑修复脚本**。

### 8.4 图标类

见 [二、exeico](#二exeico--图标提取) 的项目封装表。

### 8.5 分析类

| 脚本 | 职责 |
|------|------|
| `parse_logs.py` | 解析 Total Uninstall 监控日志，生成写入行为分析表 |
| `analyze_batch.py` / `analyze_wemeet.py` | 批量/单软件写入行为分析 |
| `detect_installer.py` | 识别安装包类型（NSIS/Inno/MSI/在线 stub） |
| `deep_reg.py` | 深度注册表写入分析 |
| `probe_*.py` 系列 | 探针脚本：probe_electron（Electron 环境）、probe_wrapper（包装层）、probe_nsis_env（NSIS 环境）等，用于定位特定问题 |
| `check_bat.py` | 校验批处理脚本 |

### 8.6 使用约定

- **新软件优先接入通用构建器**（往 build_batch 配置中加参数），不手工复制旧配置；
- 配置生成后**必须过验证类脚本**（verify_redirect + test_portable）才算完成；
- probe 系列是调试工具，问题定位后保留，不删除（是后续同类问题的排错资产）；
- 运行环境：Python 3.x，Windows；**项目约定调试优先用 Python，避免用 PowerShell 调试**。

## 九、系统内置工具

| 命令 | 用途 |
|------|------|
| `schtasks /delete /tn "任务名" /f` | 删除软件注册的计划任务（Custom.nsh 中调用） |
| `taskkill /f /im "进程名"` | 强制结束后台残留进程（Custom.nsh FuncEnd 钩子） |
| `tasklist` | 验证后台无残留进程 |
| `reg query` / `reg export` | 验证注册表键已清理 / 备份注册表 |
| `net stop` / `sc query` | 检查软件是否注册了系统服务（有则不适合便携化） |
| `sigcheck`（Sysinternals） | 校验安装包数字签名 |

## 十、虚拟机测试环境

**硬性要求**：便携包**必须在干净虚拟机或沙箱中测试通过**才算完成，不得只在开发机上验证。

**推荐配置**：

- 干净的 Windows 10 22H2 (19045) 虚拟机快照（与本项目已验证环境一致）；
- 每次测试前回滚到干净快照，避免上一次测试的残留干扰结论；
- Windows 11 兼容性按需加测（TSF 机制一致，理论兼容）。

**虚拟机验收清单**（与制作方法.md 第十节一致）：

1. 注册表键正确读写，退出后 HKCU 相关键已移除；
2. `%APPDATA%`、`%LOCALAPPDATA%` 下无软件目录残留；
3. 后台无残留进程；
4. 复制到不同盘符路径，配置仍可读取；
5. 崩溃/强杀后重启能恢复一致状态；
6. `Data\debug.log` 无报错。
