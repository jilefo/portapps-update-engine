## 一、项目定位与核心价值

GreenSoftMake 是一个面向 Windows 平台的 **绿色软件 / 便携软件工业化制作项目**。其核心目标是：在不修改原软件二进制的前提下，通过 **注册表映射（绿色化）** 或 **数据目录重定向（便携化）** 两条技术路线，把日常高频软件改造为"删除目录即完全脱离系统、不留任何残留"的可迁移形态。

### 1.1 两条技术路线对比

| 维度 | 绿色化（Green） | 便携化（Portable） |
|------|----------------|--------------------|
| 核心机制 | 注册表 CLSID/TIP 映射到绿色目录 | 环境变量 + Launcher 重定向数据目录 |
| 系统侵入 | 仅写注册表，不复制文件到系统目录 | 不写系统目录，数据全部在 `Data\` |
| 适用对象 | 输入法（TSF 框架）、WPS Office | Electron/VS Code 系 AI 客户端、Zoom 等 |
| 卸载方式 | 运行 `_卸载.bat` 清理注册表 | 直接删除整个目录 |
| 典型模板 | WeType 输入法模板 | PortableApps.com Launcher (PAL) |
| 代表成品 | Iime、WindInput、WPS | ZoomPortable、CursorPortable 等 21 个 |

### 1.2 项目成熟度判断

- **绿色化路线**：已进入 **v2.0 生产级**。具备自动提权、文件完整性校验、注册表备份、静默部署、退出码自检、HKCU 用户级注册补全等企业级特性。
- **便携化路线**：已进入 **批量工业化阶段**。`Work\` 目录已产出 21 个 `*Portable` 成品包，并配套自动化构建、启动包装、数据重定向验证、便携性测试四类 Python 工具链。

## 三、核心方法论：九步工业化工作流

项目的灵魂文件是 [portable-green-software-full-prompt.md.md](file:///<旧工作区>/portable-green-software-full-prompt.md.md)。它把"做一个便携软件"从经验手艺，压缩成一条可复现、可审计、可分批的流水线。

### 3.1 九步工作流（每个软件强制执行）

| 步骤 | 动作 | 产出物 |
|------|------|--------|
| 1 | 读取该软件目录下的 README、注册表项目日志、文件和文件夹监控日志 | — |
| 2 | 输出日志分析结果表（注册表写入位置 / 文件系统写入位置 / 写入类型 HKCU/HKLM/用户目录/系统目录） | 分析表 |
| 3 | 判定制作等级并说明理由 | 等级判定 |
| 4 | 选择模板并说明原因 | 模板选择 |
| 5 | 生成 `appinfo.ini` | 配置 |
| 6 | 生成 `launcher.ini`，所有键/路径必须可溯源到第 2 步日志 | 配置 |
| 7 | 生成 `Custom.nsh`，仅处理开机自启 / 计划任务 / 后台进程强杀 | 配置 |
| 8 | 生成人工操作指南（PAL 编译步骤 + 虚拟机测试清单 + 风险） | 文档 |
| 9 | 输出该软件制作报告条目 | 报告条目 |

### 3.2 五批次执行顺序（控制风险、便于评审）

1. 第一批：Zoom、WeMeet
2. 第二批：WeType、WindInput、Iime、WPS
3. 第三批：Cursor、Trae CN、Qoder CN、CodeBuddy CN
4. 第四批：CodeArts、CodeArts Agent、Comate、JoyCode
5. 第五批：AiPyPro、OfficeAce、Today CN、妙手、WorkBuddy、MiniMax Code、LibreWolf

每批开始前先声明范围、等用户确认；每批结束后输出汇总表格。

### 3.3 七条"禁止事项"（质量红线）

- 不得猜测注册表键和文件路径，必须来自日志；
- 不得把安装日志、卸载注册表项、监控日志、安装包放入最终便携包；
- 不得将卸载注册表项导入最终用户系统；
- 不得在未分析日志的情况下编写 `launcher.ini`；
- 不得对需要服务、驱动、Shell 扩展、实时监控的软件强行便携化（直接标记不适合并说明原因）；
- 不得读取或复制 PAL 工具目录中的文件；
- 不得一次性处理所有软件，必须分批。

### 3.4 关键配置模板片段

`launcher.ini` 按需组合以下四类能力，所有路径/键名必须可溯源：

- **启动配置**：`[Launch] ProgramExecutable=...`
- **命令行重定向**：`CommandLineArguments=--user-data-dir="%PAL:DataDir%\settings"`
- **环境变量重定向**：`[Environment] APPDATA / LOCALAPPDATA / USERPROFILE → %PAL:DataDir%\...`
- **注册表便携化**：`[Activate] Registry=true` + `[RegistryKeys]` + `[RegistryCleanupIfEmpty]`（清理顺序必须先深后父）
- **文件路径重写**：`[FileWrite1] Type=Replace` 把宿主绝对路径改写为便携相对路径

## 四、绿色化路线：输入法 v2.0 生产级方案

README 详细定义了冰凌（Iime）与清风（WindInput）两款输入法的绿色化方案，是当前项目最成熟的子模块。

### 4.1 技术原理

- 参考 WeType 模板，手工重建 TSF（Text Services Framework）注册结构；
- 输入法以 COM 组件形式注册在 `HKLM\SOFTWARE\Classes\CLSID`，路径指向绿色目录（`%~dp0`）；
- CTF TIP 注册在 `HKLM\SOFTWARE\Microsoft\CTF\TIP`，`Enable=1` 启用语言配置；
- 用户级切换列表注册在 `HKCU\Software\Microsoft\CTF\SortOrder`，保证 Win+Space 可切换；
- 快捷键注册在 `HKCU\Software\Microsoft\CTF\DirectSwitchHotkeys`。

### 4.2 v2.0 相对 v1.0 的十项改进

1. 新增 HKCU SortOrder 注册 —— 修复清风输入法无法进入切换列表的根因缺陷；
2. 新增 DirectSwitchHotkeys 注册 —— 统一 Ctrl+Space 切换快捷键；
3. 文件完整性校验 —— 缺文件退出码 3，拒绝半成品注册；
4. 注册表备份 —— 绿化/卸载前自动导出到 `backup\`；
5. 静默参数 `/silent` —— 支持企业无人值守分发；
6. 错误处理与自检 —— 每步失败即退出并返回非零退出码；
7. 自动 UAC 提权 —— 非管理员双击自动请求；
8. 修复 IimServer 自启残留 —— 不再写指向原版安装路径的 Run 键；
9. 卸载脚本补全 HKCU 清理 —— SortOrder / DirectSwitchHotkeys / Assemblies 一一对应删除；
10. 结束后重启 ctfmon —— 保证输入法框架即时生效。

### 4.3 退出码语义化

| 退出码 | 含义 |
|--------|------|
| 0 | 成功 |
| 1 | 参数错误 |
| 2 | 提权被取消 |
| 3 | 目录内文件缺失 |
| 4 | 注册表写入失败 |
| 5 | 自检失败（注册不完整/有残留） |

### 4.4 部署注意事项（已沉淀为开源文档）

- 先卸载原版，避免 CLSID 冲突；
- GUID 来自原版安装，跨机器通用，仅路径指向本目录；
- 已在 Windows 10 22H2 (19045) 验证，Windows 11 理论兼容；
- 部署后请勿移动目录（注册表路径会失效）；
- HKCU 项仅对当前用户生效，多用户需各自运行一次；
- `_绿化.bat /silent` 适合企业分发，退出码可被自动化脚本消费。

## 六、自动化工具链（_analysis 目录）

项目并非纯手工制作，已沉淀出一套 Python 自动化工具链，是"工业化"二字的真正支撑。

| 脚本 | 职责 |
|------|------|
| `build_launcher.py` | PAL 启动器 EXE 构建器；定义 `App\AppInfo\Launcher` 结构要求、`appinfo.ini` 必需字段、`makensis` 编译入口 |
| `build_batch3.py` | 第三批 VS Code/Electron 系便携包通用构建器；集中定义 Cursor / Trae CN / CodeBuddy CN / Qoder CN / WorkBuddy 的主程序、版本、AppInfo 与 launcher 参数 |
| `launcher_wrapper.py` | Electron 类便携包启动包装脚本生成器（解决脏环境变量与数据重定向） |
| `test_portable.py` | 便携包自动测试框架；对每个包执行启动、进程存活、Data 增长、宿主残留四项检查 |
| `verify_redirect.py` | 数据重定向验证工具；对比启动前后 `Data\` 与宿主 `APPDATA/LOCALAPPDATA` 的文件变化，判定是否存在宿主写入泄漏 |

**质量闭环**：构建（build）→ 包装（wrap）→ 重定向验证（verify）→ 便携性测试（test），四个脚本共同构成便携包的出厂质检线。

## 七、运维与生命周期管理

### 7.1 日志体系（Logs 目录）

`Logs\` 按软件名建立 17 个子目录，分别存放对应软件的：安装/卸载注册表导出（`.reg`）、文件和文件夹监控日志（`.txt`）、安装配置（如 wps 的 `install.ini`、`installfilelist.dat`）、差分备份（`diffbase\`）。这是九步工作流第 1、2 步的唯一事实来源。

### 7.2 批量清理 / 归档（cleanup-manifest.json）

`cleanup-manifest.json` 记录了 2026-10-14 22:35:41 一次 **dry-run** 模式的批量清理计划，覆盖 17 个便携包。每条目包含：

- `pkg`：便携包名；
- `source`：原始软件名；
- `bytes`：占用体积（如 FoxitPDFPortable ≈ 4.3 GB，OfficeAcePortable ≈ 2.3 GB，TraeCNPortable ≈ 1.7 GB）；

17 个包合计体积约 **16.4 GB**，是磁盘空间治理的重要对象。该清单证明项目已具备"批量、可审计、可回滚（dry-run 先跑一遍）"的运维意识。

## 九、优势、风险与改进建议

### 9.1 核心优势

1. **方法论完备**：九步工作流 + 七条禁止事项 + 五批次节奏，把"手艺"变成了"工艺"。
2. **双路线清晰**：绿色化与便携化边界明确，各自有成熟模板（WeType / PAL）。
3. **工具链闭环**：构建、包装、重定向验证、便携测试四脚本，质量不靠人肉保证。
4. **可审计可回滚**：日志先行、dry-run 清理、注册表备份、退出码语义化。
5. **企业级意识**：`/silent` 静默部署、UAC 自动提权、多用户说明、完整性校验。

### 9.2 潜在风险

| 风险 | 说明 | 等级 |
|------|------|------|
| 法律合规 | README 已声明"不含输入法本体，请获取正版授权"，但 21 个便携包中部分商业软件（Foxit、OfficeAce、Zoom、腾讯会议等）的再分发授权需逐一确认 | 高 |
| 注册表路径失效 | 绿色化方案部署后移动目录即失效，需在使用文档中反复强调 | 中 |
| 多用户场景 | HKCU 项仅对当前用户生效，企业批量部署需配套登录脚本 | 中 |
| 更新维护成本 | 商业软件高频更新，便携包跟进压力大，Sandboxie 方案尚未定论 | 中 |
| dry-run 清理未落地 | cleanup-manifest 仍处于 dry 状态，17 个包 16.4 GB 占用持续存在 | 低 |

### 9.3 改进建议

1. **尽快落地任务 7（开源化）**：把 `docs\archive\制作方法.md`、`docs/04-避坑手册.md`、`docs\archive\工具说明.md` 补全，并明确 GitHub 仓库与开源协议；这是项目从"个人工具"走向"社区资产"的关键一步。
2. **完成任务 6（更新策略）**：在 Sandboxie 方案 A 与官方离线包方案 B 之间做决断，并把更新脚本并入 `_analysis` 工具链。
3. **落地清理计划**：将 `cleanup-manifest.json` 从 dry-run 转为正式执行（或给出执行时间表），回收磁盘空间。
4. **补齐 WeMeet 评估报告**：按任务 3 要求输出可行性结论，避免长期悬而未决。
