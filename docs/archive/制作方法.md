## 一、选路决策：绿色化还是便携化

拿到一个软件，先判定路线，再动手：

```
软件是否需要系统服务 / 驱动 / Shell 扩展 / 实时监控？
├── 是 → 不适合便携化，直接标记并说明原因，停止
└── 否 → 是否写 HKLM 或系统目录？
        ├── 是 → 绿色版（PAL + 临时清理，见第六节）
        └── 否（仅写 HKCU 与用户目录）→ 便携版（PAL 标准结构，见第四节）
```

**类型默认策略**：

| 软件类型 | 默认路线 |
|----------|----------|
| 输入法（TSF 框架） | 绿色版（注册表映射） |
| WPS Office | 绿色版（COM 集成深，便携会损失功能） |
| AI 类客户端（Electron / VS Code 系） | 便携版优先，无法便携时降级绿色版 |
| 官方已有便携版（如 LibreWolf、Qoder CN） | 直接下载整理，不重复制作 |
| 社区已有成熟方案（如 zmPortable） | 优先复用社区方案 |
| 插件型（CodeArts / Comate，运行于宿主 IDE） | 与 VS Code 便携版打包，不单独做插件便携版 |
| CLI 工具（MiniMax Code） | 天然便携，直接放入 `App\` |

## 二、九步工业化工作流

每个软件严格按以下九步执行，**不得跳步**：

| 步骤 | 动作 | 产出物 |
|------|------|--------|
| 1 | 读取该软件目录下的 README、注册表项目日志、文件和文件夹监控日志 | — |
| 2 | 输出日志分析结果表：**注册表写入位置 / 文件系统写入位置 / 写入类型**（标注 HKCU 或 HKLM、用户目录或系统目录） | 分析表 |
| 3 | 根据分析结果判定制作等级，并说明判定理由 | 等级判定 |
| 4 | 选择模板，说明选择哪个模板以及为什么 | 模板选择 |
| 5 | 生成 `appinfo.ini` 内容 | 配置 |
| 6 | 生成 `launcher.ini` 内容。**所有注册表键和文件路径必须来自第 2 步的日志分析表**，并在配置中用注释标注对应的日志行号或关键字 | 配置 |
| 7 | 生成 `Custom.nsh` 内容，**仅处理三类问题**：开机自启、计划任务、后台进程强制结束 | 配置 |
| 8 | 生成人工操作指南：PAL 编译启动器步骤、虚拟机测试检查清单、已知限制和风险 | 文档 |
| 9 | 输出该软件的制作报告条目 | 报告条目 |

**七条质量红线（禁止事项）**：

1. 不得猜测注册表键和文件路径，必须来自日志；
2. 不得把安装日志、卸载注册表项、监控日志、安装包放入最终便携包；
3. 不得将卸载注册表项导入最终用户系统；
4. 不得在未分析日志的情况下编写 `launcher.ini`；
5. 不得对需要服务、驱动、Shell 扩展、实时监控的软件强行便携化，应直接标记为不适合便携化并说明原因；
6. 不得读取或复制 PAL 工具目录中的文件（仅供人工编译）；
7. 不得一次性处理所有软件，必须分批处理。

**模板选择参考**：

| 模板 | 参考点 |
|------|--------|
| `Template Center\ZoomPortable` | PAL 标准结构、launcher.ini、RegistryKeys、RegistryCleanupIfEmpty、Custom.nsh |
| `Template Center\LibreWolf-Portable` | Profiles 目录管理 |
| `Template Center\VscodiumPortable` | VS Code 架构的 `--user-data-dir` 与 APPDATA 重定向 |
| `Template Center\WeType` | 输入法绿色化：注册表最小化写入、外挂进程处理、禁止自动更新 |

## 三、分批执行策略

不得一次性处理所有软件。按以下批次执行，**每批开始前先声明本批范围并等确认，每批结束后输出汇总表格**：

| 批次 | 软件 |
|------|------|
| 第一批 | Zoom、WeMeet |
| 第二批 | WeType、WindInput、Iime、WPS |
| 第三批 | Cursor、Trae CN、Qoder CN、CodeBuddy CN |
| 第四批 | CodeArts、CodeArts Agent、Comate、JoyCode |
| 第五批 | AiPyPro、OfficeAce、Today CN、妙手、WorkBuddy、MiniMax Code、LibreWolf |

**输出格式要求**：分析结果用 Markdown 表格；配置文件输出完整文件内容并标注目标路径，方便直接保存；操作指南用编号清单；所有 Windows 路径字符串统一加双引号。

## 四、便携化标准结构（PAL）

便携包采用 PortableApps.com 标准目录结构：

```
{软件名}Portable\
├── {软件名}Portable.exe       # PAL 启动器（外层入口，人工编译产物）
├── App\
│   ├── AppInfo\
│   │   ├── appinfo.ini        # 元数据：名称、版本、AppID、发布者
│   │   └── Launcher\
│   │       └── {软件名}Portable.ini   # 启动器配置（核心）
│   ├── DefaultData\           # 首次运行的默认数据（可选）
│   └── {软件名}\              # 主程序与全部依赖（从安装包提取）
├── Data\                      # 用户数据 / 设置（被重定向的真实写入位置）
└── Other\                     # 源文件、许可等（可选）
```

**要点**：

- `Data\` 是用户数据的唯一真实落点，**永不覆盖**；
- `App\AppInfo\` 下的 launcher.ini、appinfo.ini、Custom.nsh 是自定义资产，更新时只改版本号，不整体替换；
- 安装日志、卸载注册表项、监控日志、安装包**一律不得放入**最终便携包；
- 官方提供 `-portable.zip` 时，直接下载新版覆盖 `App\`，这是最省事的方式。

## 五、launcher.ini 配置详解

以下配置片段按需组合，**不要直接照搬**；路径和键名必须来自该软件的实际监控日志。

**启动配置**：

```ini
[Launch]
ProgramExecutable={软件名}\{主程序}.exe
```

**命令行重定向**（VS Code 系典型）：

```ini
[Launch]
ProgramExecutable={软件名}\{主程序}.exe
CommandLineArguments=--user-data-dir="%PAL:DataDir%\settings"
```

**环境变量重定向**：

```ini
[Environment]
APPDATA=%PAL:DataDir%\settings
LOCALAPPDATA=%PAL:DataDir%\settings\local
USERPROFILE=%PAL:DataDir%\settings\user
```

**注册表便携化**：

```ini
[Activate]
Registry=true

[RegistryKeys]
settings=HKCU\Software\{厂商}\{软件名}
config=HKCU\Software\{厂商}\{软件名}\Config

[RegistryCleanupIfEmpty]
1=HKCU\Software\{厂商}\{软件名}\Config
2=HKCU\Software\{厂商}\{软件名}
3=HKCU\Software\{厂商}
```

> **注意**：`RegistryCleanupIfEmpty` 的编号顺序必须**先清理深层子键，再清理父键**，否则父键因尚有子键而无法删除。

**文件路径重写**：

```ini
[FileWrite1]
Type=Replace
File=%PAL:DataDir%\settings\config.ini
Find=C:\Users\
Replace=%PAL:LastDrive%:\PortableApps\{软件名}Portable\Data\settings\
```

## 六、绿色版降级方案（PAL + 临时清理）

当软件因写 HKLM 或系统目录而无法完全便携时，降级为绿色版。核心策略：**启动时导入、退出时反向导出并彻底清理**。

在 `Custom.nsh` 中实现：

- `FuncOnStart`：导入配置注册表，启动软件；
- `FuncOnExit`：结束进程，把注册表反向导出到 `Data\`，然后**彻底删除**已导入的注册表键；
- 若软件关闭不可靠，增加**启动前检测并清理上一次异常残留**的逻辑。

**绿色版底线**：运行结束后，宿主系统中不应存在软件留下的持久性数据。

**必须在 `help.html` 中明确标注为绿色版**，说明运行期间可能对系统产生临时改动、异常关闭后需要手动清理的具体位置。

## 七、常驻后台与自启清理

视频会议和输入法类软件有强系统集成倾向，必须检查并处理：

1. **开机自启**：清理 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 中的自启项；
2. **计划任务**：使用 `schtasks /delete` 删除相关任务；
3. **后台进程**：退出主程序后，`WeMeetApp.exe`、`Zoom.exe`、输入法外挂进程可能仍在后台，需在 `Custom.nsh` 的 `FuncEnd` 钩子中强制结束；
4. **服务与驱动**：若软件安装服务或驱动 → 标记为不适合便携化，停止并说明原因；
5. **Shell 扩展**：若软件安装 Shell 扩展 → 标记为不适合便携化，停止并说明原因。

## 八、各软件制作要点

> 以下要点来自主提示词的生产实践沉淀，路径与键名仍以各软件**最新监控日志**为准。

### 第一批

- **Zoom**：最容易成功，优先完成。直接复用 `Template Center\ZoomPortable`，把当前版本的 `bin` 内容替换到 `Work\ZoomPortable\App\Zoom\bin`；更新 appinfo.ini 版本号；对照 Zoom 注册表日志更新 launcher.ini 的 RegistryKeys 与 RegistryCleanupIfEmpty；Custom.nsh 确认包含结束 `Zoom.exe` 后台进程的逻辑。
- **WeMeet（腾讯会议）**：复制 ZoomPortable 作为骨架。App\Zoom → App\WeMeet；appinfo.ini 改 Name=腾讯会议 Portable、AppID=WeMeetPortable；RegistryKeys 映射 `HKCU\Software\Tencent\WeMeet`，RegistryCleanupIfEmpty 依次清理 WeMeet 与 Tencent；Environment 重定向 APPDATA/LOCALAPPDATA/USERPROFILE；Custom.nsh 强杀 `WeMeetApp.exe` 并删除 Run 自启项。**卸载注册表项仅用于分析，绝不导入最终用户系统**。

### 第二批

- **WeType**：直接复用模板，更新程序文件到目标版本，确认外挂进程常驻处理、注册表最小化写入、自动更新拦截均有效；help.html 标注为绿色版。
- **WindInput（清风）**：官方有便携版则直接收录；否则参考 WeType 绿色方案。重点：外挂进程常驻、注册表最小化写入、禁止自动更新。
- **Iime（冰凌五笔）**：本身设计即支持免安装，直接整理到 `Work\IimePortable`；确认无注册表写入，或有写入时用 PAL 清理。
- **WPS**：制作绿色版。用 Total Uninstall 监控安装，提取注册表与文件系统差异；配置数据重定向到 `Data\settings`；launcher.ini 映射 WPS 的 HKCU 键。help.html 必须说明功能损失：**右键新建、系统级 COM 加载项、云文档同步将不可用，PDF 转 Word 等高级功能可能报错**。

### 第三批（VS Code / Electron 架构）

- **Cursor、Trae CN**：参考 VscodiumPortable。`CommandLineArguments=--user-data-dir="%PAL:DataDir%\settings"`；Environment 重定向 APPDATA/LOCALAPPDATA；插件目录、用户配置、对话记录数据库纳入 `Data\`。**Trae CN 的对话记录加密绑定机器指纹与工作区 ID，跨机器复制后无法读取——这是设计限制，不是制作缺陷**。Cursor 官方无 ZIP 安装包时，需从安装包中提取文件。
- **Qoder CN**：官方提供含 `-portable` 的 ZIP 时直接解压收录；便携版默认连本地模型端点，不写注册表、不碰 PATH。注意 `Qoder CN` / `Qoder CN IDE` / `QoderCNIDE` 可能是同一软件的重复条目，若是则只制作一个。
- **CodeBuddy CN**：官方提供 `*_x64-portable.zip` 时直接解压；确认 WebView2 运行时依赖（Win10/11 通常已内置）。

### 第四批（插件型）

- **CodeArts、CodeArts Agent、Comate**：本体运行在宿主 IDE 中，推荐把 **VS Code 便携版与插件一起打包**，而不是单独制作插件便携版；参考 VscodiumPortable 配置。
- **JoyCode**：先确认是独立 IDE 还是插件版，按对应类型处理。

### 第五批（需逐一分析写入行为）

- **AiPyPro**：Python 应用，重点重定向 APPDATA 与 USERPROFILE，检查 Python 缓存目录。
- **OfficeAce**：WebView2 应用，安装包大，检查 WebView2 缓存目录并重定向到 `Data\`。
- **Today CN**：桌面客户端，检查用户数据目录、缓存目录、日志目录。
- **妙手**：ERP 客户端，先确认是否为 WebView2 封装，检查注册表写入与本地数据库路径。
- **MiniMax Code**：终端 CLI、独立二进制，天然便携，直接放入 `App\MiniMaxCode`，确认无注册表写入即可。
- **WorkBuddy**：官方无绿色版，社区有非官方便携启动器。**使用社区启动器必须标注风险：非官方渠道存在封号风险，首次运行仍需联网准备官方运行时**；自行制作则按 WebView2 应用处理。
- **LibreWolf**：**不制作**。官方已有便携版，`Template Center\LibreWolf-Portable` 仅作 Profiles 管理参考。

## 九、输入法绿色化完整技术方案（v2.0）

以冰凌（Iime）/ 清风（WindInput）为例的生产级方案，纯注册表绿化，不复制任何文件到系统目录。

### 技术原理

- 参考 WeType 模板手工重建 TSF（Text Services Framework）注册结构；
- 输入法以 COM 组件形式注册在 `HKLM\SOFTWARE\Classes\CLSID`，路径指向绿色目录（`%~dp0`）；
- CTF TIP 注册在 `HKLM\SOFTWARE\Microsoft\CTF\TIP`，`Enable=1` 启用语言配置；
- 用户级切换列表注册在 `HKCU\Software\Microsoft\CTF\SortOrder`，保证 Win+Space 可切换；
- 快捷键注册在 `HKCU\Software\Microsoft\CTF\DirectSwitchHotkeys`。

### 绿化流程（`_绿化.bat`）

1. 参数解析（`/silent` `/noshortcut`）；
2. 提权（非管理员自动 UAC）；
3. 文件完整性校验（缺文件退出码 3）；
4. 备份现有注册表到 `backup\`（带时间戳）；
5. 结束相关进程（Iimsrv / Iimpe / Iimkit / wind_input / wind_setting）；
6. 清理旧注册（HKLM CLSID 64/32 + CTF TIP）；
7. 注册 CLSID（64/32 位 InProcServer32，ThreadingModel=Apartment）；
8. 注册 CTF TIP（Category 8~16 项 + LanguageProfile Enable=1）；
9. 注册用户级切换列表（SortOrder 动态追加索引 + DirectSwitchHotkeys）；
10. 写入应用键（WindInput 的 InstallDir 与 URL Protocol）；
11. 创建桌面快捷方式（可选）；
12. 重启 ctfmon；
13. 自检关键注册项，全部通过才报成功。

### 卸载流程（`_卸载.bat`）

1. 结束相关进程；
2. 备份现有注册表到 `backup\`；
3. 清理 HKLM（CLSID 64/32 + TIP + 应用键）；
4. 清理 HKCU SortOrder（按 CLSID 匹配删除）；
5. 清理 HKCU DirectSwitchHotkeys（按 CLSID 匹配删除）；
6. 清理 HKCU Assemblies 默认指向；
7. 删除桌面快捷方式；
8. 重启 ctfmon；
9. 自检无残留。

## 十、调试与验证人工清单

使用 PAL 生成**调试版启动器**，运行后查看 `Data\debug.log`，重点观察：

1. 注册表键是否正确读取和写入 `.reg` 文件；
2. 环境变量替换是否在正确时机生效；
3. `FileWriteN` 的查找和替换是否命中目标字符串；
4. 软件退出后，HKCU 下相关键是否已从宿主注册表移除；
5. `%APPDATA%`、`%LOCALAPPDATA%` 下相关目录是否未被创建（或已清理）；
6. 把整个便携目录**复制到不同盘符路径**下，软件是否仍能正常读取先前保存的配置；
7. 软件崩溃或强制结束后，重新启动时是否能恢复一致性状态；
8. 后台无残留进程。

**必须在干净虚拟机或沙箱中测试**。测试通过后，可用 PortableApps.com Installer 打包为 `.paf.exe`；若不分发，保留便携目录及启动器 `.exe` 即可直接使用。

## 十一、更新维护

### 十条原则

1. `Data\` 目录**永不覆盖**；
2. `App\AppInfo\` 下的 launcher.ini、appinfo.ini、Custom.nsh 是自定义资产，**永不整体覆盖**，只按需改版本号与新增配置；
3. 先备份再更新：每次更新前把整个便携包复制到 `Backup\{软件名}\{旧版本号}`，保留最近三个版本；
4. 更新后必须**重新分析**注册表与文件写入行为（新版可能新增键、改变数据目录、引入服务/驱动）；
5. 官方便携包优先：直接下载新版覆盖 `App\`，不重复制作；
6. 官方无便携包时，从安装包提取：优先 7z 解包或静默安装到临时目录，**不要安装到系统**；
7. 不依赖软件内置自动更新，必须拦截或重定向；
8. 启动器 exe 通常不需要重新编译，除非主程序路径或启动参数变化；
9. 每次更新后必须在干净虚拟机跑一遍验证清单；
10. 社区成熟方案优先跟进，不自己追版本。

### 标准更新流程

1. 获取新版官方包，校验数字签名与 SHA256；
2. 停止软件运行，确认后台无残留进程；
3. 备份当前便携包到 `Backup\{软件名}\{版本号}`；
4. 解压新版到**临时目录**（不要直接解压进便携包）；
5. 对比新旧 `App\` 目录，确认新增/修改/删除文件；
6. 替换 `App\` 下程序文件，保留 `App\AppInfo` 不动；
7. 更新 appinfo.ini 的 Version 与 DisplayVersion；
8. 重新分析监控日志，按需更新 launcher.ini 的 RegistryKeys / RegistryCleanupIfEmpty / Environment / FileWriteN；
9. 用 PAL 重新生成调试版启动器，查看 `Data\debug.log`；
10. 干净虚拟机验证：注册表无残留、用户目录无残留、后台无进程、配置可保存；
11. 确认无误后删除临时目录，保留备份。

### 按类型更新要点

- **VS Code 架构**：只替换 `App\{软件名}` 程序文件；`Data\settings` 中的 User、extensions、ModularData 保留；插件可能不兼容，让软件自行迁移或重装；新版若改变 `--user-data-dir` 行为，更新 CommandLineArguments。
- **官方便携版**：新版 `-portable.zip` 覆盖 `App\`，保留 `Data\`；若官方包自带 launcher.ini 且结构变化，合并自定义配置；更新版本号。
- **插件型**：插件本体在 `Data\settings\extensions` 下；下载新 `.vsix` 在便携 IDE 中离线安装或替换扩展目录；宿主 IDE 单独按 VS Code 架构更新；**不要覆盖整个 Data**。
- **WebView2 应用**：更新 `App\` 程序文件；检查新版是否改变 WebView2 缓存路径；内置自动更新必须拦截或重定向到 `Data\`。
- **输入法与 WPS**：输入法更新频繁，建议直接复用社区最新绿化版；WPS 更新时**重新监控安装过程**（注册表键与 COM 组件可能变化），更新后重点检查右键菜单、COM 加载项是否被意外注册到系统。

### 更新后验证清单

- 软件能正常启动，版本号显示为新版；
- 用户配置、插件、对话记录仍在；
- 注册表无残留：退出后 `HKCU\Software\{厂商}` 下相关键已清理；
- 用户目录无残留：`%APPDATA%`、`%LOCALAPPDATA%` 下无软件目录；
- 后台无残留进程；
- 复制到不同盘符路径，配置仍可读取；
- 调试日志无报错；
- 已知限制和风险已更新到 help.html。

## 十二、升级器开发指引

**是否开发升级器**：

| 场景 | 建议 |
|------|------|
| 个人自用少量软件 | 不开发完整升级器，手工更新 + 半自动脚本 |
| 团队多机器、几十款软件、每周更新 | 可开发轻量级便携升级器 |
| 面向多人分发 | 优先自建 PAF 更新源，用 PortableApps.com Platform 管理更新，**不要自己写升级器** |

**推荐执行路径**：

1. 先不要开发完整升级程序；
2. 为每个软件建立一份更新配方文档（YAML/JSON：下载 URL、版本解析规则、静默安装参数、提取目录、排除/保留目录、需检查的 launcher.ini 项、已知限制）；
3. 写一个 PowerShell 半自动脚本，只做：版本检测、下载、校验、备份、替换 `App\` 程序文件、改版本号；
4. 脚本运行后，**人工**检查 launcher.ini 是否需要更新、人工用 PAL 重生成启动器、人工虚拟机测试；
5. 软件数量超过 15 个、每周更新、多台机器使用时，再升级为通用便携升级器。

**关键提醒**：配方文件由人工维护，升级器只执行、不自动推断；不要自动导入安装包里的注册表，不要自动运行卸载程序；自动化只能做下载、校验、备份、替换文件、改版本号，**配置校验和测试必须人工确认**。
