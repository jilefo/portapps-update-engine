主# 更新维护方案对比（任务 6 结论文档）

> 范围：本项目 22 个便携包的后期更新维护路线选择。
> 关联：[制作方法.md](制作方法.md) 更新章节、主提示词"十条更新原则"、WeMeet 更新工具链实战（2026-10-15）。

## 一、候选方案

### 方案 A：Sandboxie Plus 沙盒提取

**流程**：沙盒内静默安装新版本 → 从沙盒文件系统导出变更文件 → 覆盖便携包 `App\`。

**优势**
- 能处理**无法静态解包**的安装器：自研安装器、安装时联网下载本体的 stub、MSI 复杂变换
- 安装过程被完整捕获，天然附带一次"写入行为分析"（契合更新原则 4：更新后重新分析写入行为）
- 不污染宿主

**劣势**
- 引入重量级外部依赖（Sandboxie 驱动级软件）；**本机当前未安装**，团队/用户机器需统一部署
- 沙盒内安装可能因驱动/服务受限而**与真实安装行为不一致**（腾讯系软件常带驱动/服务组件，沙盒内可能拒绝安装或静默跳过）
- "沙盒文件变更 → 可靠导出"环节缺乏成熟工具，需自行写 diff 提取脚本，维护成本高
- 自动化链路长（沙盒配置、静默参数、导出比对），任一环节失败都需人工介入

### 方案 B：官方离线包解包（主流路线）

**流程**：下载官方离线完整安装包 → 7z/InnoExtract/MSI 静默解包 → 提取程序文件 → `robocopy /MIR` 覆盖 `App\`（排除 AppInfo 与 Data）→ 更新 appinfo.ini 版本号。

**优势**
- 直接、确定性高：拿到什么文件就是什么文件，无沙盒行为偏差
- 自动化程度高：解包、替换、版本号更新全部可脚本化（WeMeet 的 `update.ps1` 已实测通过）
- 与项目现有工具链（7z、robocopy、`_analysis` Python 脚本）无缝衔接

**劣势**
- 依赖"能拿到离线包"与"能解开包"两个前提：
  - 部分官网为 SPA 动态页面，**下载直链无法程序化获取**（腾讯会议实测：CDN URL 带随机 hash、查询 API 失效）→ 需"人工点一次下载 + 脚本全自动接管"的半自动模式
  - 自研加密安装器可能 7z 解不开 → 回退方案 A 或手工安装后提取

### 方案 C：软件自带更新器（有条件放行）

**流程**：使用软件内"检查更新"，让更新器直接升级便携包内程序文件。

**优势**：零维护成本；增量更新省流量。

**劣势与红线**
- 主提示词更新原则 9 明确要求：**不依赖软件内置自动更新，必须拦截或重定向**。自带更新器可能写宿主目录、注册表、计划任务、开机自启，破坏便携性
- **放行条件（全部满足才允许）**：经实测验证更新器 ① 只写便携包 `App\` 目录；② 不产生宿主残留；③ 更新后 junction/重定向仍然有效；④ 不需要管理员提权写系统目录
- 当前状态：腾讯会议自带更新组件（package_update.dll）理论兼容便携结构，**待下次官方发版实测**后决定是否放行；其余软件默认一律拦截

## 二、对比总表

| 维度 | A 沙盒提取 | B 离线包解包 | C 自带更新器 |
|------|-----------|-------------|-------------|
| 适用安装器 | 全部（含不可解包） | 可静态解包的（NSIS/Inno/MSI/压缩包） | 仅限验证放行的软件 |
| 自动化程度 | 低（多人工环节） | 高（可全/半自动） | 全自动（一旦放行） |
| 可靠性 | 中（沙盒行为可能失真） | 高（确定性文件操作） | 低-中（更新器行为不可控） |
| 外部依赖 | Sandboxie Plus（驱动级） | 7-Zip（轻量、本机已有） | 无 |
| 维护成本 | 高（需自研 diff 提取） | 低（脚本已沉淀） | 极低 |
| 数据安全 | 高（Data 不参与） | 高（Data 不参与，实测验证） | 中（需验证不碰 Data） |
| 与十条原则契合度 | 完全契合 | 完全契合 | 默认冲突，须例外审批 |

## 三、推荐结论

**以方案 B 为主干路线，方案 A 为兜底备选，方案 C 例外放行。**

1. **默认走 B**：每个便携包配 `_更新.bat`（参照 WeMeet 实现），离线包可解包的软件全部脚本化半自动更新。官网无法直链下载的，采用"人工触发下载 + 脚本监视 Downloads 自动接管"模式（已验证为当前最优解）。
2. **A 仅在 B 失效时启用**：遇到 7z/InnoExtract 解不开的自研安装器、或 stub 安装器（安装时才下载本体）时，再引入 Sandboxie；启用前需先解决沙盒内安装保真度验证。
3. **C 默认拦截**：自带更新器一律按原则 9 拦截/重定向；仅当某软件实测满足四条放行条件（见上）后在文档中登记例外。WeMeet 为当前唯一候选，待发版实测。
4. **更新前后纪律不变**（十条原则兜底）：更新前备份到 `Backup\{软件}\{旧版本}`（保留三版）、更新只动 `App` 不碰 `AppInfo`/`Data`、更新后重新分析写入行为并重跑虚拟机验证清单。
