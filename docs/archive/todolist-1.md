## 优化后的任务清单（可直接下发）

### 任务 1：修复便携启动器图标（默认图标 → 原程序图标）

**问题描述**：你编译的便携启动器图标全部显示为默认图标，不符合要求。需要为每个便携版启动器使用对应原程序的图标。

**执行要求**：
1. 使用已配置 PATH 的 `exeico` 命令行工具，从原程序 EXE 中提取图标。
2. 提取命令参考：`exeico exe <原程序.exe路径> <输出.ico路径>`
3. 将提取的图标嵌入/关联到便携启动器 EXE 中。
4. 如果原程序有多个图标变体（不同尺寸/状态），优先使用主图标。

**验收标准**：启动器在文件资源管理器、任务栏、Alt+Tab 切换中均显示原程序图标，而非默认空白图标。

### 任务 2：Zoom 便携版制作（核心任务，含问题排查）

**背景**：已建立 `<旧工作区>/ZoomPortable` 目录，要求制作 Zoom 便携版。

**问题排查（优先级最高）** ：

用户反馈“打开 ZoomPortable 目录后浏览器自动下载 ZOOM”，原因大概率是 Zoom 安装包或启动器触发了 **Zoom 的浏览器协议唤醒（zoommtg://）** ，或安装脚本调用了在线安装器而非离线安装包。

**排查步骤**：
1. 检查 `ZoomPortable` 目录中是否存在指向在线安装器的脚本/快捷方式。
2. 检查是否有 `zoommtg://` 协议被意外触发。
3. 确认使用的 Zoom 安装包是否为 **离线完整安装包**（MSI 或完整 EXE），而非在线 stub 安装器。

**制作规格**：
- 使用 **zmPortable**（PortableApps.com 已有成熟方案）作为参考或直接集成。
- 便携启动器需处理 Zoom 的用户数据目录重定向（避免写入 `%APPDATA%\Zoom`）。
- 启动器图标使用任务 1 中提取的 Zoom 原图标。

**缺失文件处理**：如果缺少安装包或依赖文件，去 `%USERPROFILE%\Downloads` 查找对应版本安装程序。优先使用离线完整安装包。

**验收标准**：双击启动器后，Zoom 正常启动，用户数据写入便携目录，不触发浏览器自动下载。

### 任务 3：WeMeet 便携化可行性评估（先调研，后执行）

**背景**：用户提出疑问——“Zoom 能便携，为什么 WeMeet 只能绿色化？”

**执行要求**：
1. **先做可行性调研**，不要直接动手制作。调研内容包括：
   - WeMeet（腾讯会议）的安装程序类型（是否依赖系统级服务/驱动/注册表）。
   - 是否有官方或社区已有的便携方案参考。
   - 哪些组件可以绿色化，哪些必须写系统目录。
2. 如果可行性高，参照 Zoom 便携版方案执行。
3. 如果可行性低（例如强依赖系统服务），**输出一份简短的评估报告**，说明技术障碍，并给出替代建议（如沙盒方案）。

**说明**：WeMeet 与 Zoom 的安装架构不同，Zoom 有成熟的 PortableApps 方案，而腾讯会议可能涉及系统级组件。不要因为 Zoom 能做就默认 WeMeet 一定能做。

### 任务 6：后期更新维护方案 — 沙盒方案评估

**问题**：后期更新维护是否采用 Sandboxie Plus 方案——静默安装到沙盒，然后提取文件覆盖？

**执行要求**：
1. **调研 Sandboxie Plus 的便携模式**。Sandboxie Plus 安装程序本身支持“Extract all files to directory for portable use”选项。
2. 评估两种更新方案的可行性：
   - **方案 A**：沙盒内静默安装新版本 → 提取变更文件 → 覆盖便携目录。
   - **方案 B**：直接下载官方离线安装包 → 解包提取 → 覆盖便携目录。
3. 对比两种方案在自动化程度、可靠性、维护成本上的差异。
4. 输出**方案建议文档**，说明推荐方案及理由。

**注意**：Sandboxie 本身是沙盒工具，用沙盒来“提取”安装文件是可行思路，但需确认沙盒内的文件变更是否能被可靠导出。
